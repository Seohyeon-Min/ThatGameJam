# Model size test scene Sam_model_test

## Why

The user wanted a place to look at the ladybug model (`01-무당벌레-모델과-애니메이션.md`). First, two ladybugs went into the Main intro stage. Then the user asked for a separate scene instead of Main. The conditions:

- The scene name is `Sam_model_test`
- A girl for size comparison, the old tree, and a few trees around. Later the user asked for the bird too
- The girl walks slowly forward
- None of Main's intro sequence (the bird flying around at the start, and so on)
- Take the ladybugs out of the intro and put them in this scene

## Key decisions

- **Component name.** The first `LadybugCrawler` followed the Terrain height. The new scene is a flat Plane, and the girl must move too. So it became `WaypointWalker`, and the Animator Bool name became a setting. The height follows the points.
- **Girl start state.** The Girl controller's default state is `Sleep`. With `Asleep` off, it first plays the 12.6-second `GetUp`, and walking during it slides. So `startState` is `Idle`, which starts her standing.
- **Girl speed.** The game's `babyWalkSpeed` is 1.2 m/s. For "slowly" it is 0.6 m/s. The walk animation is unchanged, so the feet may slide a little.

## The flapping sound

The user said a flapping sound kept playing although there was no bird. In Play Mode, every FMOD event instance was checked. The only one playing was `event:/SFX/footstep_snow`. The `Footstep` events of the girl's `Girl_Walk` clip (0 s and 0.6 s) play it through `BabyAnimationEvents`. In the FMOD project this event uses `footstep_snow_0 ~ 3.wav`. The bird's `event:/SFX/flap` comes only from the `Bird_Flap` clip, and the scene had no bird before. So the sound heard is taken to be the girl's snow footsteps. With the bird added, its `Hover` clip has no events, so no flap plays.

## Cross-model review

GPT-6.1 Sol. Lenses: correctness, security, robustness. Two reviews. The first covered `LadybugCrawler` and the placement builder for the intro. The second covered the current code.

| Level | Finding | Handling |
|------|---------|----------|
| warn | An empty `points`, or a null in it, throws (both reviews) | **Dismissed.** These are settings fixed in the scene. If one is wrong, the exception shows in the console at once. The project avoids overly defensive code |
| warn | If something fails after the new scene is made, that scene stays the active scene | **Applied.** Filling and saving are wrapped in `try`/`finally`, which makes the original scene active again and closes the new one |
| warn | The `SaveScene` return value is ignored | **Applied.** A failure returns `FAILED to save` |
| — | The builder change that adds the bird (`BuildBird`, `CopyLook`) | At first `codex exec` failed with `Your workspace is out of credits`. After the credits were refilled it ran again: `LGTM - no blockers` |
| warn | Releasing the button still flies on to the last target, unlike "flies only while held" | **Dismissed, comment fixed.** The intent is to go where you click. The comment read as "while held", so it now says a click sets the target and holding keeps moving it with the mouse |
| warn | `CopyLook` changes a prefab instance's meshes, materials and Animator without recording overrides, so they may be lost on reopening | **Dismissed.** The saved scene file has 17 `m_Mesh`, 17 `m_Materials.Array.data[0]` and 2 `m_Controller` overrides. Rebuilding with `RecordPrefabInstancePropertyModifications` gave the same, so it was not added |
| warn | The intro placement builder does not check that the scene is Main, and deletes the old objects before checking anything | **Not applicable.** That builder is deleted |
