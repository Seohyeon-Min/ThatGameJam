# Tree kind 1 (`Tree_1_Bare`) floated 2.5 m; it now stands on the ground

## Why

The user reported trees floating in mid-air in stage 3.

We compared the tree heights in `Main` with the terrain height. Every tree stood at the terrain height. But every tree placed from `Tree_1_Bare` floated. `Tree_2_Bare`, `Tree_3_Bare` and the leafy trees stood on the ground.

| Where | Tree | Height above the ground |
|------|------|------|
| `Stage3` (MazeTrees, Wall, TerrainTrees) | 144 `Tree_1_Bare` | 2.1 to 2.9 m |
| `01_SYSTEM/TreeGenerator` | 468 `Tree_1_Bare` | 3.7 to 8.5 m |

Cause:

- `Tree_1_Bare.prefab` overrode the position of the FBX root `tree01` with `(0.086, 2.5156, 0.120)`. The value was saved when the prefab was made on 10-28.
- The value equals the position of the `tree_base` node in the current FBX. We think the old FBX had `tree_base` as its only top node, so Unity used it as the root and the value matched the original position. We did not open the old FBX to check.
- Commit `ef62f6a` on 11-02 (Tommy, "fixed 3 tree meshes not combined as single mesh") added a second top node, the combined mesh `Tube`, to `tree01.fbx`. Unity made a new root `tree01` at the origin, and the leftover override lifted that root by 2.52 m.

## What changed

| What | Where |
|------|------|
| Reverted the position override on `tree01` to `(0, 0, 0)`, in the Editor with `PrefabUtility.RevertPropertyOverride` | `Assets/03_Prefabs/Trees/Tree_1_Bare.prefab` |
| Saving again also wrote `alwaysExempt: 0`, a field newly added to `Perchable` | same file |

## Verification

| What | Result |
|------|------|
| Opened `Main` additively and measured, per tree, the gap between the renderer bottom and the tree position | 0.00 m for all 468 trees of the three kinds in `Stage3` |
| Prefab mesh | bottom y 0.00, top 5.56 |
| Ray down onto the mesh from above `PerchPoint` (placed on 10-29 in `d8cea92` for grounded trees) | hits the wood at y 2.94; the perch is on the branch again |
