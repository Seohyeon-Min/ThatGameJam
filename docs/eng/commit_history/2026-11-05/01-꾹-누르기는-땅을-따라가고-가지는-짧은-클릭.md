# Holding follows the ground under the pointer, and a branch needs a short click to perch on (ADR 0030)

## Why

The director's order, item 1 (`order_from_director.md`). Holding the button to go ahead, the bird goes hesitantly. Measured in Play Mode: while held, whenever the pointer passed over a roadside tree's perch spot, the target point jumped to that tree. The measurement and the decision are in [ADR 0030](../../decisions/0030-holding-follows-the-ground-and-a-short-click-perches.md).

## What changed

| What | Where |
|------|------|
| The held-follow target looks only at the ground under the pointer (`Ground`, `ClickPlane`). Branches count only for perching | `BirdController.cs` `Update` |
| A press on a branch waits as `pressedPerch`. Let go within 0.2 s, `ClickPerch`; held longer, `Click` on the ground at that moment and follow. A cutscene lock or the open encyclopedia clears the wait | `BirdController.cs` `Update`, `ClickPerch`, `Click` |
| The perch cursor shows only while the button is up, or while a press on a branch is still young | `BirdController.cs` `Update` |
| `Click` split into the branch click (`ClickPerch`) and the ground click (`Click`); hopping again while walking (`HopAgain`) moved into the ground click | `BirdController.cs` |
| `birdPerchClickSeconds` = 0.2 | `GameTuning.cs` |
| The bird controls description | `docs/kor/implementation_plan.md`, `docs/eng/implementation_plan.md` |

`GameTuning.asset` was not edited. The asset has no value for the new field, so the code default 0.2 is used. The value goes in the next time the Editor saves the asset.

## Verification

Main scene, Play Mode. Skipped the intro and pressed with a virtual mouse (`InputSystem.AddDevice`) in stage 1. Logged the bird's state, target point and the ground point under the pointer every frame.

| What | Result |
|------|------|
| Before the fix, one point up-right of the bird held for 7 s | Target on a tree in 33% of the frames. 7 jumps of 5 to 12 m. Heading −18° to +31° |
| After the fix, held the same way for 4 s | Target at most 0.62 m from the ground under the pointer (the log is one frame late). Heading −6.8° to +2.3°. At the end of the area (z 8.35) it perched on a branch and shook its head (ADR 0016, unchanged) |
| Pressed on a branch, let go after 0.1 s | Waited 0.04 s, then `ToPerch` to that branch at the release, and landed |
| Pressed on a branch and held for 2 s | After 0.2 s `Flying`, `following` on, target the ground under the pointer (−11.26, 11.59). It did not perch on that branch |
| Compile | 0 errors. Warnings only from other files, as before |

The Editor had no focus, so the virtual mouse's input did not reach the game. So, only inside Play Mode, two Input System settings were changed (`backgroundBehavior` = `IgnoreFocus`, `editorInputBehaviorInPlayMode` = `AllDeviceInputAlwaysGoesToGameView`) and the real keyboard and mouse were turned off. Afterwards the settings were put back, the virtual mouse removed, the real devices turned on, and Run In Background turned off.

Trial and error. At first a copy of the settings was made and put into `InputSystem.settings`. Restarting Play Mode, the domain reload lost that copy and the Input System kept failing to initialize. Fixed by pointing the hidden state object's (`InputSystemObject`) settings back at the original settings and reloading scripts. After that, the original settings object's values were changed after entering Play Mode (`InputManager.ApplySettings`) and put back before leaving it.

## Cross-model review

GPT-6.1 Sol, correctness and robustness lenses (input edges, cutscene lock, encyclopedia, `clicksLocked`, sheltering, a branch becoming unperchable).

| Level | Finding | Handling |
|------|------|------|
| warn | The release does not recheck the press length. Let go on the very frame 0.2 s passes, it perches | **Dismissed.** One frame. A press that long is between a click and a hold, so either is fine |
| warn | If `PerchOn` sets `clicksLocked` while a branch press waits, the wait overrides that landing | **Dismissed.** `PerchOn` is only called at the end of the intro (`IntroSequence`). The bird is under intro control then, so no wait can exist |
| warn | If no ground is under the pointer at the moment it becomes a hold, that press never follows | **Dismissed.** The click plane covers everywhere the bird can fly. The old follow relied on the same |
| warn | If the waiting branch is destroyed, the wait is skipped | **Dismissed.** Perchables are not destroyed at runtime. A falling log and the like turn `CanPerch` off. The release checks `CanPerch` and on-screen |
