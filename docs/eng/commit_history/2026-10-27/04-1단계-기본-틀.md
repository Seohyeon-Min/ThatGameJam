# Step 1: shared framework and grey-box stage 1

## Why

The user asked to start step 1 of Section 6 of the implementation plan ([`implementation_plan.md`](../../implementation_plan.md)). It counts as done when "wake → walk → stop at the log → (bird perches or 30 s) → cross → sleep in the Sunlit Rest Area → move to the next stage" runs through in one go, both when the bird helps and when the player waits.

## Key decisions

- Three coder subagents (bird, baby and log, flow and camera) wrote the code in parallel. To keep the parts that meet each other consistent, the five shared contract files were written and compiled first, and then the work was split
- A device's "resolved" and "path open" are separate. The log opens the path only after its fall animation ends, so the baby never walks onto a log that is still falling
- The bird's pointer position input is now `PassThrough`. As `Value`, with several mice the device with the largest value (the real mouse) won, so virtual mouse clicks went to the wrong place. Now the most recently moved mouse is used
- Section cameras aim 1.5 above the road and sit a little farther away, so the leaning log's top is in frame

## Cross-model review

Codex, twice. The first pass used the correctness, robustness, and security lenses. The second used the Unity pitfalls, web build limits, and getting-stuck lenses. Scope: the `.cs` files in the staged diff.

| Finding | Resolution |
|---------|------------|
| warn. When the section changes, only the target is clamped into the area; the bird itself stays outside until it flies in | Dismissed. Intentional: the bird flies into the new section instead of teleporting |
| warn. The bird does not unsubscribe from its perch's `Released` when destroyed | Dismissed. The bird lives for the whole game and is destroyed only when the scene unloads |
| warn. If a `Stage`'s start references are empty, gizmo drawing throws every frame | **Fixed.** This happens when a teammate builds a stage by hand. Nothing is drawn while they are empty |
| warn. If the log object is disabled during its fall, the coroutine stops and the path never opens | Dismissed. No code disables the log or the baby |
| warn. If the baby is disabled and re-enabled while walking, it does not move again | Dismissed, for the same reason. Every stage start resets it with `PlaceAsleep` |
| warn. `GameFlow` never unsubscribes from the baby's `ReachedRest` | Dismissed. `GameFlow` and the baby live and die together in the same scene |

## Remaining

- The baby's poses, the bird's cry, and the log's signals are placeholder motion of grey boxes. When art arrives, Animator and sound go onto the signal events
- Testing used scripted virtual mouse input. Nobody has played it by hand with a real mouse yet
- While the bird flies from outside into a new section, it can be off screen
