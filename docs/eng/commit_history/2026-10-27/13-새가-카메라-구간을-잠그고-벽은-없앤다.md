# Camera zones lock when the bird crosses the trigger, and there is no wall stopping the bird (ADR 0008)

## Why

The director changed the trigger from the baby to the bird, and asked to remove the invisible wall. Trying it, the user found the camera moved a lot upward while locked, and asked for a much smaller range. Since the basics keep changing, the user also said not to apply changes to the fog map or test it.

## What changed

| What | Where |
|------|-------|
| The trigger is now a line across the road (Z) instead of a point (radius 1). The bird crossing it locks the zone. `BirdCamera` passes the bird's position only to the current stage's zones. Removed the wall (`wall`, `IsWallUp`, `WallZ`) | `Assets/02_Scripts/Flow/CameraZone.cs` |
| Zone checks only for the current stage's zones. Removed the wall from the bird's range | `Assets/02_Scripts/Flow/BirdCamera.cs` |
| Builder. Removed the wall argument. The log zone's range from center z 19.5, 4 × 5 to center z 17.5, 2 × 1. Fog 3-2 trigger from z 18.5 to z 20 (builder code only). Rebuilt `Sam_Test` only | `AgentScripts/BuildSamTestScene.cs`, `Assets/00_Scenes/Sam_Test.unity` |
| The decision and rejected alternatives | ADR 0008 |
| Camera sentences, and that the fog map is on hold | `implementation_plan.md` chapter 1, 3.1, 4.1, 4.7, 4.18, 5.1 Q3, 6.1 |

## Key decisions

- The fog map (`Sam_Fog_Test.unity`) is unchanged in this commit; it is the previous commit's scene. It still has fields the current code lacks (`wall`, `triggerRadius`), which Unity ignores. When the user says the fog map work starts, it is rebuilt with the code of that time
- Every builder run renumbers the internal IDs in `Bird.controller`. When the content is the same, it is not committed

## Verification

In `Sam_Test`'s Play Mode, the bird was moved by code. Not tried with a real mouse. The fog map was not tested.
