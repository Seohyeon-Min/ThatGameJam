# Convert the design PDF to Markdown and write the code implementation plan (ADR 0003)

## Why

The user added a mostly final design document, `Game Design.pdf`, to the project root. The user asked for three things.

- Read the design document and write down what the code side will implement
- Convert the PDF to `.md` so it is easy to refer to later
- Delete the earlier design draft `rough_game_design.md`

After reading the plan, the user answered 11 of the 13 questions in Section 5. Q10 (when fog and natural resolution overlap) was left undecided. For Q11 (the last cry in the ending), the user asked back what it means.

## What changed

| What | Where |
|------|-------|
| Added `Game Design.pdf` to the repository | Root |
| Converted the PDF to Markdown. The content is unchanged. Tables that broke in the PDF text extraction were put back into their original rows and columns | `docs/kor/game_design.md` |
| English translation of the document above | `docs/eng/game_design.md` |
| Code implementation plan. Shared framework, implementation direction per system, gaps with the current code, decided and open questions, work order, risks | `docs/kor/implementation_plan.md` |
| English translation of the document above | `docs/eng/implementation_plan.md` |
| Answers to 11 plan questions and rejected alternatives | ADR 0003 |
| Deleted the earlier design draft | `docs/kor/rough_game_design.md`, `docs/eng/rough_game_design.md` |

## Key decisions

- The original design document is a Korean PDF. So this time `kor` is the original and `eng` is the translation. The earlier draft was the other way around ([08](../2026-10-26/08-기록-양식-전환과-기획-문서-이동.md))
- The answers to the plan questions are in ADR 0003. Three were decided differently from the proposal: the shared game scene is `Main.unity`, the camera uses Cinemachine, and the bird cannot leave the screen of the current section camera
- For Q11, Section 5.2 of the plan records what §12.2 and §12.3 of the design doc say and do not say. It stays open
