# Play Girl_Jump stepping onto/off the balance beam (log)

## Why

Repo owner's suggestion: "what about playing the jump animation when the baby climbs up onto and down off the tree (log)." This is exactly the spot `Girl_Jump` was left for in the 10-29 session — an Animator state built but "not decided where to use it (coming down off the log, a small obstacle, or left for later)."

## What changed

| What | Where |
|------|-------|
| Added a `jumpClip` field (`Girl_Jump`, 1.5s). A `PlayJump()` coroutine: stands still, crossfades into the `Jump` state, waits out the clip's length | `Baby.cs` |
| Inserted `yield return PlayJump()` right before switching to `BalanceWalk`/`Walk` at three spots: reaching the start (`BalanceBeamStart`) and end (`BalanceBeamEnd`) of a beam segment, and when the leaning log (`LeaningLog`) falls open and the baby starts crossing it | `Baby.cs` (`WakeAndWalk`) |
| Wired the `Baby` component's `jumpClip` field to the `Girl_Jump` clip | `Sam_Test.unity` |

## Key decisions

- All three spots (beam start, beam end, LeaningLog) share the same coroutine — they're all the same condition ("about to change balance-beam state, standing still"), so there was no reason to write it three times.
- Stays put (`StandStill()`) while the jump plays. Kept the existing separation between actual movement (`transform.position`, driven by `StepToward`) and visual flourishes: `WalkTo` already puts the baby exactly at the point before `PlayJump` runs, so even though the clip itself has a leap, it plays as an in-place hop at the spot already reached.
- Left the Animator Controller's `Jump` state untouched — it was already built in the 10-29 session with no authored transitions (entered and exited only by script `CrossFade`).
