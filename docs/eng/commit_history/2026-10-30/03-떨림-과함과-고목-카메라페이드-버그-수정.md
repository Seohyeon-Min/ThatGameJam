# Fixed the baby's shiver being too intense, and camera fade erasing the LeaningLog device

## Why

The repo owner personally spotted two problems: (1) the baby trembles "like an aspen tree" — asked whether this session's point-of-interest work caused it. (2) (relayed secondhand) the camera fade also erases the LeaningLog device.

## What changed

| What | Where |
|------|-------|
| Lowered cold-shiver intensity/frequency (2.5°/9Hz → 0.8°/3.5Hz). Applied on both axes at once, it was strong and fast enough to read as the whole body buzzing like a doll | `GameTuning.cs` |
| Added an `alwaysExempt` option to `Perchable`. When on, the object stays camera-fade-exempt always, not just while the bird is perched on it. Decorative roadside branches (`idleSpot`) still fade like background; only LeaningLog's `Trunk` (a device the player must interact with) got it turned on | `Perchable.cs`, `Sam_Test.unity` (`alwaysExempt: 1` on LeaningLog/Trunk) |

## Key decisions

- The shiver is unrelated to this session's point-of-interest (glance) work. Glance only touches the head bone, and only for 1.5s every 4–9s. The shiver was the full-body tremor code in `Baby.cs`'s `Update()`, added in the previous session (`04a0531 baby movement`, before I was involved). Explained this clearly to the user.
- Swept every `Perchable` instance in the scene: the only "device" one is LeaningLog's `Trunk`; everything else is a decorative roadside-tree idle perch (`idleSpot=true`). So `alwaysExempt` was applied only to LeaningLog, not blanket-applied — the roadside branches fading like background is the intended look.
- **Found an important trap:** `GameTuning.asset` had none of yesterday's/today's new tuning fields (`babyShiver*`, `babyGaze*`, `babyWander*`, etc.) actually serialized — they were all silently relying on the C# field defaults. With that in place, changing a C# default and recompiling does **not** take effect in an Editor that has already loaded the asset into memory once (the native object was already deserialized with the old default, and a domain reload doesn't re-apply the new default to it). Had to write the values explicitly into the `.asset` file and force a reimport (`AssetDatabase.ImportAsset(ForceUpdate)`) to actually pick them up. Going forward, any new `GameTuning` field needs an explicit value written into the asset too.

## Verification

| What | Result |
|------|--------|
| Compile `GameTuning.cs` / `Perchable.cs` | `script recompile` → `completed`, 0 errors |
| Set `alwaysExempt=true` on LeaningLog's `Trunk`, then read the renderer's `_CameraFadeExempt` shader property directly in Play Mode | `1` (exempt even with no bird perched) |
| After forcing a reimport of the `.asset`, read `GameTuning.Current.babyShiverAngle`/`Frequency` | Correctly `0.8`/`3.5` (before the forced reimport it still read `2.5`/`9`, which is how the trap above was found) |
| `git diff` | `Sam_Test.unity` changed by exactly one line (`alwaysExempt: 1`) — confirmed only the intended change |

## Remaining

- The new shiver numbers (0.8°/3.5Hz) are an estimate tuned to stop reading as "buzzing" — haven't seen on screen yet whether it now reads as a believable cold shiver. May need another pass after playtesting.
- Stages not built yet (2-2 rabbit family, 3-1–3-3 fog/cloud) will likely hit the same camera-fade problem on their own devices. Remember to turn on `Perchable.alwaysExempt` (or equivalent handling for a non-Perchable device) when building those.
