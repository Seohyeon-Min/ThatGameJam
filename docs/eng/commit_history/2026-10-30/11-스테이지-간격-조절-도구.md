# Stage spacing inspector tool

## Why

Repo owner's suggestion: "what about making a space adjuster between stages." Right before this (record 10), the Intro→Stage1 gap was widened by hand-scripting it; the ask was to make that a reusable inspector tool instead of a CLI one-off each time.

## What changed

| What | Where |
|------|-------|
| `Stage.AdjustSpacing(float deltaZ, bool cascadeToLaterStages)`: shifts this stage's own transform (everything under it — route, start points, tree generators) and its `area` (the bird's flight bounds) along +Z by `deltaZ`. With `cascadeToLaterStages` on, applies the same shift to every stage **after** this one in `GameFlow`'s authored order too (so those stages keep their own existing mutual gaps, and only this boundary's gap changes). Off, only the gap right before this stage changes (same as what was done to Intro in record 10) | `Assets/02_Scripts/Flow/Stage.cs` (`#if UNITY_EDITOR` block, same pattern as `TreeGenerator.Generate`/`Clear`) |
| Added a read-only `GameFlow.Stages` accessor (exposes the existing `stages` array for the cascade to read) | `Assets/02_Scripts/Flow/GameFlow.cs` |
| Inspector UI: a `Shift Along Road (Z)` field, an `Also shift every later stage` toggle, and an `Apply` button | `Assets/02_Scripts/Flow/Editor/StageEditor.cs` (new file, same UIElements pattern as `TreeGeneratorEditor`/`SeasonEditor`) |

## Key decisions

- Doesn't touch the shared terrain (streams, where a log sits, anything under `World`) — only moves what the `Stage` itself owns (its children, its `area`). Same boundary record 10 already drew ("editing terrain is out of scope").
- With cascading on, "stages after this one" is resolved through `GameFlow.stages`'s **authored order**, not scene hierarchy order or Transform Z values — hierarchy order isn't reliable for this.
- Defaults to adjusting one boundary at a time (cascade off = only the gap right before this stage). Didn't build a single operation that repositions a whole chain at once — press it stage by stage if several boundaries need adjusting; can add a bulk version later if that's actually needed.
- Supports Undo (`Undo.RecordObject` on both the transform and the `area`) — a bad value is one Ctrl+Z away from undone.

## Verification

| What | Result |
|------|--------|
| Compile | `script recompile` → `completed`, 0 errors |
| Called `Intro.AdjustSpacing(5, false)` then reverted with `-5` | Only Intro moved (-15 → -10), `Stage1` untouched, reverting landed exactly back at -15 |
| Called `Stage1.AdjustSpacing(3, true)` then reverted with `-3` | Both `Stage1` and `Stage2` moved together, reverting landed exactly back at 0 for both |
| `git diff` after the round-trip tests | `Main.unity` shows no change at all (no floating-point drift either — landed exactly back) — only the 3 scripts (`Stage.cs`, `GameFlow.cs`, new `StageEditor.cs`) changed |
| Console | 0 errors |
