# Tree placement becomes a `TreeGenerator` component other scenes can use

## Why

The director asked for it (Tree Generator). Tree placement (`PlaceRoadsideTrees()`) was a function inside `BuildSamTestScene`, so using it meant running the whole builder. That also rebuilt `Sam_Test.unity` and the tree prefabs, so it was hard to use in other scenes. The director wants to drop tree prefabs into their own test scene and place them right away with Generate.

## What changed

| What | Where |
|------|-------|
| `TreeGenerator`, attached to a scene object. The Inspector sets the tree prefab list, several areas (two corners in X, Z relative to that object), spacing, jitter (a fraction of the spacing), size range, random rotation, and seed. The areas always show as green outlines in the Scene view | `Assets/02_Scripts/Tools/TreeGenerator.cs` |
| The placement is the builder's, unchanged: a jittered grid, neighbours of different kinds (if all are taken, the kind whose nearest tree is farthest), random rotation and size | `TreeGenerator.cs` |
| Generate and Clear buttons in the Inspector and "trees made by this generator". Generate removes the trees that generator made and places new ones. Clear removes only the trees that generator made. One Ctrl+Z undoes either | `Assets/02_Scripts/Tools/Editor/TreeGeneratorEditor.cs` |
| The builder makes a `RoadsideTrees` object under stage 1, attaches this component, and calls Generate. `PlaceRoadsideTrees` is gone | `AgentScripts/BuildSamTestScene.cs` |
| `Sam_Test` rebuilt. The tree prefabs were saved again and only the IDs inside the files changed. The scene points at the new IDs, so they are committed together | `Assets/00_Scenes/Sam_Test.unity`, `Assets/03_Prefabs/Trees/` |
| The `TreeGenerator` and dev tool sentences | `implementation_plan.md` 3.1, 4.18, 6.1 |

## Important decisions

- "The trees this generator made" is a list the component serializes. Other things under the same object are not removed by Clear
- Tree height is the object's height (local y = 0). Ground height is not measured, as before
- Random numbers are drawn even when random rotation is off or the size range is a single value. Changing only that setting then keeps the trees' places and kinds
- Undo: the list changes first, then the trees are removed. When placing, the list changes after all trees exist. `Undo.DestroyObjectImmediate` and `RegisterCreatedObjectUndo` commit the changes recorded so far, so in the opposite order the list came back empty on undo (it did in the first test)

## Verification

| What | Result |
|------|--------|
| `script recompile` | 0 errors |
| Compared the 56 trees of the scene before the change with the scene the builder rebuilt after it (prefab, position, rotation, scale as `R`-format strings) | All the same |
| Clear → Ctrl+Z → Generate → Ctrl+Z (`Undo.PerformUndo`), with one child the generator did not make | Children 57 → 1 → 57 → 57 → 57. Trees in the list 56 → 0 → 56 → 56 → 56, all under the generator. The other child stayed |
| Generate with spacing 0 | Warned and did nothing. Spacing 1 on a 3 × 3 area gave 9 trees |
| Generate with a scene object in a prefab slot | Warned and left the 9 existing trees as they were |
| Console | 0 errors and warnings |

The Inspector buttons were not clicked by hand. The same functions were called from a script.

## Cross-model review

Codex. Correctness (same result as before, Undo order), security, and robustness lenses. Scope: the diff of the builder and the two new `.cs` files.

| Finding | Resolution |
|---------|------------|
| warn. On a new component with a null areas array, Generate throws, after Clear has already removed the trees | Fixed. Both arrays start empty |
| warn. `Min` on spacing guards only the Inspector. A script setting 0 or less makes the loop endless and freezes the Editor | Fixed. Before Clear, a spacing below 0.1 warns and stops |
| warn (confirmation review 1). A scene object in a prefab slot throws during placement, after the trees were removed | Fixed. Before Clear, every slot must be a prefab asset. Generate with a scene object in a slot only warned, and the 9 existing trees stayed |
| warn (confirmation review 1). Infinite or huge area coordinates make `x + spacing == x` and the loop never ends | Dismissed. Areas are typed by hand for a level tens of metres wide. Code against such values would guard a case that does not happen |

The second confirmation review after the fixes returned `LGTM - no blockers`.
