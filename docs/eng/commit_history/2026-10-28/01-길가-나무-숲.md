# Roadside trees: 8 colour-coded kinds, bare trunks, a dense random forest

## Why

The director asked for 7 to 8 kinds of roadside trees, placed at random and as dense as the reference pictures the user uploaded. The user asked to put a different kind next to each tree, to tell the kinds apart by colour for now, and to drop the round crowns. As before, the fog map gets none of this.

## What changed

| What | Where |
|------|-------|
| Removed `Tree.prefab` (trunk and round crown) and added 8 tree kinds `Tree_1` to `Tree_8`: tall bare trunks (height 10, thickness 0.35) that differ only in colour. New materials `Tree_1` to `Tree_8`; removed `Leaves.mat` | `Assets/03_Prefabs/Trees/`, `Assets/01_Arts/Materials/Test/` |
| A forest on the far side of the road (-X) in stage 1. The banks and streams reach 11 further that way. Thickness 0.8 to 1.4 times and height 0.8 to 1.2 times at random. The seed is fixed, so a rebuild gives the same forest | `AgentScripts/BuildSamTestScene.cs` |
| Rebuilt `Sam_Test` only. 98 trees | `Assets/00_Scenes/Sam_Test.unity` |
| Tree rows | `implementation_plan.md` chapter 2, 6.1 |

## Key decisions

- Trees stay on the far side of the road only. On the camera side (+X) they would hide the road
- One prefab per kind, so when the art's tree models arrive only the trunk inside each prefab changes
- Trunk thickness and height vary a little per tree; the kinds differ only by colour
- No trees in stage 2 (the temporary stage for checking the transition)
- The fog map (`Sam_Fog_Test.unity`) is unchanged. The fog builder does not use trees, and the builder's `Ground` and `Water` behave as before with the new parameter's default
- `Bird.controller` (internal IDs), `ClickMarker.mat` and `RestLight.mat`, which change on every builder run, are not committed
