# Screen effects are also drawn in the first frames, and the encyclopedia photo framing fix goes back in (ADR 0040)

## Why

After ShaderPrewarm (record 19), the web Release build still stalled late in the intro, at the start of the fog map, and at the cliff echo. In the profile (`Builds/profile/spikes_174526.txt`) the first two were the first use of the screen effects' (renderer features') shaders: about 67 ms of the 99 ms cutscene-start frame was the watercolor Kuwahara passes, and 170.8 ms of the 189 ms fog-start frame was `Dream Fog`. ShaderPrewarm only draws the scene renderers' materials, so these were left out. The cliff echo (862 ms) was not a shader. It was a bug in the encyclopedia photo framing: an empty particle system's bounds (at the world origin) went into the framing, so the photo camera backed off 297 m and drew the whole forest.

## What changed

| What | Where |
|------|-------|
| `ShaderPrewarm.Warms(camera)`: true for the target camera during the 3 prewarm frames. Volume Profile field `effectsProfile` for the screen effects' settings | `Assets/02_Scripts/Rendering/ShaderPrewarm.cs` |
| `effectsProfile` set to `GirlGetUpVolume`. The 3 profiles the game uses for the watercolor effects have the same watercolor settings (Strokes, characters only) | `01_SYSTEM/ShaderPrewarm` in `Main.unity` |
| WatercolorKuwahara, WatercolorBlur: while their Volume is off, they record their passes with that profile's settings. The output does not replace the camera colour, and since nothing reads it, culling is turned off. Blur also draws the gouache character pass | `WatercolorKuwaharaFeature.cs`, `WatercolorBlurFeature.cs` |
| DreamFog, ForestMist: drawn into a throwaway texture in the screen's format, so nothing shows whatever the weight | `DreamFogFeature.cs`, `ForestMistFeature.cs` |
| SeasonWipe: drawn into a throwaway texture with the default black texture instead of the photo. Drawing the characters again is skipped | `SeasonWipeFeature.cs` |
| Encyclopedia photo framing leaves out particle systems with no particles, zero-size bounds and disabled renderers. Same as the reverted `4389389` | `Assets/02_Scripts/Encyclopedia/Encyclopedia.cs` |

## Key decisions

- Within ADR 0040's exception. Nothing is created at runtime and no saved setting is overwritten. The effect passes draw into textures the render graph takes from its pool.
- No global keyword changes when the fog comes in (no `multi_compile` in the 5 shaders, no `EnableKeyword` in the scripts), so objects are not drawn again in a fog state.
- The framing fix had been reverted after a "the lag got worse" report. This code only runs at the moment a photo is taken. This was explained to the user, who confirmed before it went back in.
- `Cutscene.StartAfterDelay` 17 ms (Timeline graph creation) was left alone.
