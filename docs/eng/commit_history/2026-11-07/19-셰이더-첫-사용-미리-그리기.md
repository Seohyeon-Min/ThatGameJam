# Web first-use shaders are drawn ahead in the game's first frames (ADR 0040)

## Why

After shader preloading the web build still hitched now and then during the intro flight. The user asked whether to reduce cloud puffs. In the capture (`Builds/profile/spikes_174526.txt`) the median frame there was about 9 ms; nearly every frame over 50 ms was first shader use (`ApplyShader`, `CreateGPUProgram`, 64-705 ms). So first use was moved forward instead of changing puff count.

## What changed

| What | Where |
|------|-------|
| In the game's first 3 frames each of the scene's 141 materials is drawn once with `Graphics.RenderMesh`, scaled to 1e-5 in front of the camera so nothing shows. Layer, rendering layer and shadow settings come from the original renderer. It turns itself off afterwards | `Assets/02_Scripts/Rendering/ShaderPrewarm.cs`, `01_SYSTEM/ShaderPrewarm` in `Main.unity` |
| List builder: 109 materials from scene renderers (inactive too), 32 script-only materials whose shader a renderer uses. Meshes that are not saved are replaced by a quad | `AgentScripts/BuildShaderPrewarm.cs` |

## Key decisions

- [ADR 0040](../../decisions/0040-web-shader-first-use-drawn-in-first-frames.md). An exception to AGENTS.md's no-startup-code rule, allowed by the user. Cloud puffs stay.
- A separate re-save-only commit of Main.unity came first (`2c68a8b`); this scene diff is about 1,000 lines. Two WindingWater meshes only change IDs on every save.

## Verification

| What | Result |
|------|--------|
| Compile | 0 errors |
| Play Mode | 0 console errors; `ShaderPrewarm.enabled == false` at frame 495. At first the built-in quad from `GetBuiltinResource` was null and two DontSave meshes did not serialize, causing exceptions; both fixed in the builder |
| Release web build | Succeeded, 0 errors, 71,200,738 bytes, 6m36s |
| User play | Intro flight hitches nearly gone. Late intro and fog map entry hitch a little, the cliff echo a lot |
