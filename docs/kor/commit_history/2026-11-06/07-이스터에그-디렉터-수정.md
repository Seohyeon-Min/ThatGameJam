# 이스터에그 디렉터 수정: 크기, 바위 제거, 눈더미 SoftSnow, 철새 방향과 날갯짓

## 왜 했나

`order_from_director.md` 1번. 디렉터가 이스터에그 6 개의 크기, 모양, 동작을 고치라고 했다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| `HollowSquirrel` 2 배, `CornelianCherry` 2.5 배, `IcicleXylophone` 1.6 배. 프리팹 루트의 스케일이다. 안의 다람쥐, 열매, 앉는 자리도 같이 커진다 | `AgentScripts/BuildEasterEggs.cs`, 각 프리팹 |
| 고드름 실로폰 아래의 자리 표시 바위를 뺐다. 고드름은 끝 아래에 있는 것(이제 땅)까지 떨어진다. 코드는 그대로이고 주석만 고쳤다 | 같은 곳, `IcicleXylophone.cs` |
| `SnowWhirl`, `SnowFlower` 의 눈더미를 `SoftSnow.mat`(`ThatGameJam/SoftSnow` 셰이더, 소녀 몸의 눈)으로 바꿨다. 스테이지 2 의 `Snowbank` 프리팹 자체는 그대로다 | `BuildEasterEggs.Snowbank` |
| 철새 모델을 180° 돌렸다. 모델이 −Z 를 본다(새의 `visualRoot` 도 같은 이유로 180° 돌아가 있다) | `BuildEasterEggs.MigratingBirds` |
| 철새가 나는 동안 `flapEvery`(2 초)마다 `GlideFlap` 으로 크로스페이드한다. 사이에는 `Glide` | `MigratingBirds.cs` |
| 열린 씬을 저장하지 않고 프리팹만 다시 만드는 진입점 `BuildEasterEggs.BuildPrefabs` 를 나눴다. `Main` 이 저장되지 않은 변경을 가진 채 열려 있었기 때문이다 | `BuildEasterEggs.cs` |

`Main` 의 인스턴스는 스케일을 덮어쓰지 않으므로 씬은 고치지 않았다.

## 검증

| 무엇 | 결과 |
|------|------|
| `BuildEasterEggs.BuildPrefabs` 실행 | 바뀐 6 개 프리팹만 diff 가 생김. 나머지 3 개는 그대로 |
| 공터를 임시 카메라로 렌더 | 나무 두 그루와 덤불이 커짐, 바위 없음, 눈더미 두 개가 SoftSnow 모습 |
| Play Mode 에서 `MigratingBirds.Begin` 을 직접 부름 | 새 모델의 앞(−Z 를 180° 돌린 것)이 무리의 진행 방향과 같음. 상태가 `GlideFlap` 과 `Glide` 를 오감. 콘솔 에러 0 |

## 크로스 모델 리뷰

하지 않았다. 주간 사용량이 88% 라서 아꼈다.

## 남은 것

- 커진 덤불과 나무가 공터의 다른 이스터에그와 겹치는지는 그림으로만 봤다. 실제 플레이에서 새가 앉는 높이(산수유 덤불 꼭대기)를 확인해야 한다.
- 철새가 2 초 간격으로 정확히 날갯짓하는지는 CLI 호출 간격(약 2.8 초) 때문에 상태만 확인했다.
