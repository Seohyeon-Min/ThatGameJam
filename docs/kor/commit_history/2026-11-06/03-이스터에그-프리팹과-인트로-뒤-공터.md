# 이스터에그 프리팹과 인트로 뒤 공터 (ADR 0034)

## 왜 했나

디렉터 지시(`order_from_director.md`). 거의 확정된 이스터에그 기획을 나중에 모델과 위치를 바꿀 수 있게 프리팹으로 만들고, 인트로 출발점 뒤에 공터를 만들어 모두 구현해 둔다. 물웅덩이는 빼고, 질문의 답은 같은 파일 아래에 있다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 토미 브랜치의 메시 3개(고드름 나무, 구멍 난 나무, 산수유) | `Assets/01_Arts/Mesh/icy_tree`, `thickTree`, `cornelian_cherry` |
| 이스터에그 9개 컴포넌트, 사전 연결(`Discovery`), FMOD 한 번 재생(`EggSound`) | `Assets/02_Scripts/EasterEggs/` |
| 새의 쪼기·가슴 부풀리기 자리 표시, `IsOnFoot` | `BirdController.cs` |
| 최대 줌아웃 여부 `IsZoomedAllTheWayOut` | `BirdCamera.cs` |
| `Encyclopedia.Instance` | `Encyclopedia.cs` |
| 사전 항목을 새 목록 10개로 | `BuildEncyclopedia.cs`, `Assets/04_Data/Encyclopedia/` |
| 프리팹 9개와 공터, 인트로 범위 z −35, 숲 Clear 구역과 뒤쪽 패딩 1.5 m, 공터 뒤 숲 생성기 | `AgentScripts/BuildEasterEggs.cs`, `Assets/03_Prefabs/EasterEggs/`, `Main.unity` |
| Play Mode 확인 스크립트 | `AgentScripts/VerifyEasterEggs.cs` |
| 기획 정리와 지금 구현 | `easter_eggs.md`, `implementation_plan.md`, ADR 0034 |

숲을 다시 만들면서 바뀐 구운 나무 에셋(`01_Arts/Baked`)과 줄바꿈만 바뀐 파일은 커밋하지 않았다.

## 검증

| 무엇 | 결과 |
|------|------|
| `BuildEncyclopedia.Run`, `BuildEasterEggs.Run` | 성공. 월드 숲 2552 → 2514 그루, 공터 뒤 60 그루 |
| `VerifyEasterEggs.Run` (새 Play Mode, 가상 마우스) | 9개 모두 사전에 오름. 회오리 뒤 새가 다시 조작됨 |
| 게임 카메라 화면 | 공터에 나무가 없고 이스터에그가 보임 |

가상 마우스는 `editorInputBehaviorInPlayMode` 를 `AllDeviceInputAlwaysGoesToGameView` 로 바꿔야 게임에 닿았다. 스크립트가 끝나면 되돌린다. 처음에는 인트로가 끝나 계절이 1 로 오르면서 새에 쌓이는 눈이 실패했다. 확인 스크립트가 아기를 재운 채로 두게 했다.

## 크로스 모델 리뷰

GPT-6.1 Sol, 정확성·보안·견고성 렌즈.

| 지적 | 처리 |
|------|------|
| warn. 고드름의 `gravity` 0 이면 낙하 코루틴이 끝나지 않는다 | **반영.** 최소값 0.1 |
| warn. 확인 스크립트가 이미 찾은 항목을 성공으로 본다 | **반영.** 검사 전에 이미 찾았으면 그렇다고 적는다 |
| warn. 회오리·다람쥐 도중 오브젝트가 꺼지면 상태가 남는다 | **기각.** 이 오브젝트들을 끄는 코드가 없다. 생기면 그때 처리한다 |

## 남은 것

- 스테이지 안의 자리, 실제 모델(다람쥐, 눈더미, 그루터기), 쪼기·가슴 클립, 전용 소리.
- 자리가 정해지면 공터와 인트로 범위 확장, 공터 뒤 숲 생성기를 되돌린다.
