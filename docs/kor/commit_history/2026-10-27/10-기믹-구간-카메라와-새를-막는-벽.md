# 기믹 구간에서 카메라를 잠그고, 장치가 풀리기 전에는 새를 벽으로 막는다 (ADR 0007)

## 왜 했나

디렉터가 구간마다 카메라가 고정되는 방식을 원했다. 기본은 새를 따라가고, 아기가 기믹 구간의 트리거에 닿으면 카메라가 부드럽게 옮겨 가 따라가는 범위가 줄어든다. 구간을 클리어하면 풀린다. 사용자가 시험 씬에서 해 보며 차례로 셋을 더 정했다. 새도 길 밖으로 못 나간다. 아기 기준의 카메라 한계를 없앤다(디렉터 요청, 새와 아기가 따로 움직인다는 것을 보이려고). 장치를 풀기 전에는 보이지 않는 벽으로 새를 막는다.

## 중요한 결정

- 처음에는 구간이 미는 거리를 SmoothDamp 로 늦췄다. 새가 화면 안으로 밀리고, 밀린 새가 다시 점을 움직여 잠기는 순간 카메라가 목표를 지나쳤다가 돌아왔다(안개 3-1 에서 z 13.2 까지 갔다가 z 7 로). 구간마다 가중치를 두고 섞는 방식으로 바꿨다
- 벽은 콜라이더가 아니라 새 이동 범위의 Z 끝이다. 새는 물리로 움직이지 않는다

## 검증

Play Mode 에서 코드로 새를 옮기고 아기와 카메라 점의 위치를 읽었다. 실제 마우스로는 하지 않았다.

| 무엇 | 결과 |
|------|------|
| `script recompile`, 빌더 `Build`, `BuildFog` | 에러와 진단 없음 |
| 고목. 아기가 자는 동안 새를 z 40 으로 | 새와 카메라 점이 벽 z 21.5 에서 멈췄다 |
| 고목. 잠긴 상태에서 새를 (20, 40) 으로 | 새는 (5, 27)(길 끝과 화면 끝), 카메라 점은 (2, 22)(구간 끝) |
| 고목을 새가 푼 것으로 풀기 | 구간이 풀리고 새와 카메라 점이 길 끝 z 27 까지 갔다 |
| 스테이지 2 에서 새를 (-20, 5) 로 | 길 끝 x 55 에서 멈췄다 |
| 안개. 두 구간을 차례로 자연 해결 | 3-1 이 잠기고 풀린 뒤 3-2 가 잠기고 풀렸다. 카메라가 튀지 않았다. 새는 3-1 이 풀리기 전 z 19, 3-2 가 풀리기 전 z 37 에서 멈췄다. 아기가 빛나는 공간에 도착했다 |
| 콘솔 | 경고와 에러 0 |
| 시험 뒤 정리 | Run In Background 원래대로 |

## 크로스 모델 리뷰

Codex. 정확성(카메라 LateUpdate 와 새 Update 의 순서, 스테이지 전환, 구간 사이 전환, min 이 max 를 넘는 범위, null), 견고성, 보안 렌즈. 범위는 staged diff 의 `.cs` 파일.

| 지적 | 처리 |
|------|------|
| blocker. 지금 스테이지가 아닌 구간도 아기를 감지해, 같은 좌표를 쓰는 스테이지끼리 트리거가 미리 켜질 수 있다 | 기각. 스테이지는 서로 떨어진 자리에 둔다(구현 계획 3.3). `BirdCamera` 는 지금 스테이지의 구간만 읽는다. 안개 스테이지는 지금 다른 씬이다 |
| warn. 구간이 길 밖에 있거나 벽에서 너무 멀면 새의 범위가 뒤집힌다(min > max) | 반영. 배치 규칙(구간은 길 안, 먼 쪽 끝은 벽에서 `birdRange` 안)을 `CameraZone` 주석에 적었다. 지금 세 구간은 이 규칙을 지킨다. 코드로 막지는 않았다. 배치 실수이고, 막는 코드가 잘못된 배치를 숨긴다 |
| warn. `zoneEaseTime` 이 0 이하면 NaN | 반영. `[Min(0.01f)]` |

고친 뒤 다시 돌린 리뷰:

| 지적 | 처리 |
|------|------|
| warn. 새의 범위는 새의 Update 다음에 정해져, 구간이 잠기는 동안 새가 한 프레임 범위 밖에 남는다 | 기각. 전환 중 점은 한 프레임에 조금씩만 움직여 한 프레임 늦음은 보이지 않는다. ADR 0005 때부터 같은 순서다 |
| warn. min > max (위와 같은 지적) | 기각. 위와 같은 이유 |

## 남은 것

- 디렉터의 피드백을 기다린다. 기획서 §2.5 와 아직 다르다
- 구간이 잠기는 순간 새가 카메라 뒤쪽에 있으면 화면 안으로 끌려온다. 어색한지 보아야 한다
- 구간 값과 전환 시간은 임시다
