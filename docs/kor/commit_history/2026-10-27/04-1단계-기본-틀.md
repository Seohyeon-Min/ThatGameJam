## 왜 했나

## 중요한 결정

- 코드는 코더 하위 에이전트 3명(새, 아기와 고목, 흐름과 카메라)이 동시에 썼다. 서로 맞물리는 부분이 어긋나지 않도록 공통 계약 파일 5개를 먼저 쓰고 컴파일한 뒤 나눴다
- 장치의 "해결" 과 "길 열림" 을 나눴다. 고목은 해결된 뒤 쓰러지는 애니메이션이 끝나야 길이 열린다. 그래서 아기가 쓰러지는 중인 고목 위로 걷지 않는다
- 새의 커서 위치 입력을 `PassThrough` 로 바꿨다. `Value` 일 때는 마우스가 여럿이면 값이 가장 큰 장치(실제 마우스)가 이겨서 가상 마우스 클릭이 엉뚱한 곳으로 갔다. 이제 마지막으로 움직인 마우스를 쓴다
- 구간 카메라는 길 위 1.5 를 겨누고 거리를 조금 늘렸다. 기울어진 고목 꼭대기가 화면에 들어온다

## 크로스 모델 리뷰

Codex 두 번. 첫 번째는 정확성, 견고성, 보안 렌즈. 두 번째는 Unity 사용 실수, 웹 빌드 제약, 멈춰 버리는 경우 렌즈. 범위는 staged diff 의 `.cs` 파일.

| 지적 | 처리 |
|------|------|
| warn. 구간이 바뀔 때 목적지만 범위 안으로 자르고, 새의 현재 위치는 날아 들어올 때까지 범위 밖에 있다 | 기각. 순간 이동 대신 새 구간으로 날아 들어가게 하려고 일부러 그렇게 했다 |
| warn. 새가 파괴될 때 앉은 대상의 `Released` 구독을 풀지 않는다 | 기각. 새는 게임 내내 살아 있고 씬이 내려갈 때만 사라진다 |
| warn. `Stage` 의 시작 위치 참조가 비어 있으면 Gizmo 그리기에서 예외가 반복된다 | **반영.** 팀원이 스테이지를 손으로 만들 때 생기는 경우다. 비어 있으면 그리지 않는다 |
| warn. 고목이 쓰러지는 중에 오브젝트가 꺼지면 코루틴이 멈추고 길이 영원히 안 열린다 | 기각. 고목이나 아기를 끄는 코드가 없다 |
| warn. 아기가 걷는 중에 꺼졌다 켜지면 다시 움직이지 않는다 | 기각. 같은 이유. 스테이지 시작은 `PlaceAsleep` 이 매번 처음부터 다시 정한다 |
| warn. `GameFlow` 가 아기의 `ReachedRest` 구독을 풀지 않는다 | 기각. `GameFlow` 와 아기는 같은 씬에서 같이 살고 같이 사라진다 |

## 남은 것

- 아기의 자세, 새의 울음, 고목의 신호는 회색 상자를 움직이는 임시 표현이다. 아트가 오면 Animator 와 소리를 신호 이벤트에 붙인다
- 시험은 스크립트로 가상 마우스 입력을 넣어서 했다. 실제 마우스로 손으로 해 보는 것은 아직이다
- 새가 범위 밖에서 새 구간으로 날아 들어오는 동안에는 화면 밖에 있을 수 있다
