# 기획서 PDF 를 마크다운으로 옮기고 코드 구현 계획을 씀 (ADR 0003)

## 왜 했나

사용자가 어느 정도 확정된 기획서 `Game Design.pdf` 를 프로젝트 루트에 올렸다. 사용자가 세 가지를 요청했다.

- 기획서를 읽고 코드 쪽에서 무엇을 구현할지 문서로 쓴다
- 다음에도 참고하기 쉽도록 PDF 를 `.md` 로 옮긴다
- 이전 기획 초안 `rough_game_design.md` 는 지운다

계획서를 본 뒤 사용자가 5장의 질문 13개 중 11개에 답했다. Q10(안개와 자연 해결이 겹칠 때)은 미정으로 두었다. Q11(엔딩의 마지막 울음)은 무엇을 뜻하는지 되물었다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| `Game Design.pdf` 를 저장소에 넣었다 | 루트 |
| PDF 를 마크다운으로 옮겼다. 내용은 고치지 않았다. PDF 텍스트 추출에서 깨진 표는 원래 행과 열로 다시 맞췄다 | `docs/kor/game_design.md` |
| 위 문서의 영어 번역 | `docs/eng/game_design.md` |
| 코드 구현 계획. 공통 틀, 시스템별 구현 방향, 지금 코드와의 차이, 정한 것과 남은 질문, 작업 순서, 위험 | `docs/kor/implementation_plan.md` |
| 위 문서의 영어 번역 | `docs/eng/implementation_plan.md` |
| 계획서 질문 11개의 답과 버린 대안 | ADR 0003 |
| 이전 기획 초안 삭제 | `docs/kor/rough_game_design.md`, `docs/eng/rough_game_design.md` |

## 중요한 결정

- 기획서의 원본은 한국어 PDF 다. 그래서 이번에는 `kor` 가 원본이고 `eng` 가 번역이다. 이전 초안은 반대였다 ([08](../2026-10-26/08-기록-양식-전환과-기획-문서-이동.md))
- 계획서 질문의 답은 ADR 0003 에 있다. 제안과 다르게 정한 것은 셋이다. 공용 게임 씬은 `Main.unity`, 카메라는 Cinemachine, 새는 지금 구간 카메라의 화면 밖으로 못 나간다
- Q11 은 계획서 5.2 에 기획서 §12.2, §12.3 이 말하는 것과 말하지 않는 것을 적고 미정으로 두었다

## 검증

| 무엇 | 결과 |
|------|------|
| `pdftotext -enc UTF-8` 로 뽑은 PDF 의 두 글자 이상 한글 단어가 모두 `game_design.md` 에 있는지 | 빠진 단어 없음 |
| `game_design.md` 에만 있는 한글 단어 | 머리말의 출처 안내 문장뿐 |
| kor 와 eng 의 제목 줄 수와 표 줄 수 비교 (기획서, 계획서, ADR 0003, 이 기록) | 같다 |
| `docs/` 안 상대 링크가 가리키는 파일이 있는지. 양식 예시 파일은 뺀다 | 깨진 링크 없음 |

## 남은 것

- Q10, Q11 은 기획 담당에게 물어야 한다
- `AGENTS.md` 의 "`Main.unity` 는 건드리지 않는다" 규칙은 Q1 과 맞지 않는다. 사용자가 빼라고 했다. `AGENTS.md` 는 `main` 에 따로 커밋한다
- `AGENTS.md` 의 "마우스 휠은 방향만 쓴다" 규칙은 기획에서 휠을 쓰지 않게 되어 쓸 곳이 없어졌다
