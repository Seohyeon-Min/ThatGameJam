# 카메라 구간은 새가 트리거를 넘으면 잠기고, 새를 막는 벽은 없앤다 (ADR 0008)

## 왜 했나

디렉터가 트리거의 기준을 아기에서 새로 바꾸고, 투명벽을 없애라고 했다. 사용자가 시험해 보니 잠긴 동안 위쪽으로 카메라가 많이 움직여, 범위를 크게 줄이라고 했다. 사용자는 기본 사항이 자꾸 바뀌니 안개 맵에는 변경을 적용하지도, 시험하지도 말라고 했다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 트리거를 점(반경 1)에서 길을 가로지르는 선(Z)으로. 새가 넘으면 잠긴다. `BirdCamera` 가 지금 스테이지의 구간에만 새 위치를 넘긴다. 벽(`wall`, `IsWallUp`, `WallZ`)을 지웠다 | `Assets/02_Scripts/Flow/CameraZone.cs` |
| 구간 검사를 지금 스테이지의 구간으로. 새 범위에서 벽을 뺐다 | `Assets/02_Scripts/Flow/BirdCamera.cs` |
| 빌더. 벽 인자를 지웠다. 고목 구간 범위를 중심 z 19.5, 4 × 5 에서 중심 z 17.5, 2 × 1 로. 안개 3-2 트리거를 z 18.5 에서 z 20 으로(빌더 코드만). `Sam_Test` 만 다시 만들었다 | `AgentScripts/BuildSamTestScene.cs`, `Assets/00_Scenes/Sam_Test.unity` |
| 결정과 버린 대안 | ADR 0008 |
| 카메라 문장. 안개 맵을 멈춰 둔다는 것 | `implementation_plan.md` 1장, 3.1, 4.1, 4.7, 4.18, 5.1 Q3, 6.1 |

## 중요한 결정

- 안개 맵(`Sam_Fog_Test.unity`)은 이 커밋에서 바꾸지 않았다. 지난 커밋의 씬 그대로다. 그 씬에는 지금 코드에 없는 필드(`wall`, `triggerRadius`)가 남아 있지만 Unity 는 무시한다. 사용자가 안개 맵 작업을 시작한다고 할 때 지금 코드로 다시 만든다
- 빌더를 돌릴 때마다 `Bird.controller` 의 내부 ID 가 새로 매겨진다. 내용이 같으면 커밋하지 않는다

## 검증

`Sam_Test` 의 Play Mode 에서 코드로 새를 움직였다. 실제 마우스로는 하지 않았다. 안개 맵은 시험하지 않았다.

| 무엇 | 결과 |
|------|------|
| `script recompile`, 빌더 `Build` | 에러와 진단 없음 |
| 아기가 자는 동안 새를 z 16.5 로 | 잠겼다. 카메라 점 z 17 |
| 잠긴 채 새를 z 40 으로 | 카메라 점 z 18 에서 멈추고, 새는 z 23(화면 끝)까지 갔다. 벽은 없다 |
| 잠긴 채 새를 (3, 5) 로 | 카메라 점 (1, 17), 새 (2.9, 12) |
| 고목에 앉기 | 고목이 쓰러지고 구간이 풀렸다 |
| 콘솔 | 경고와 에러 0 |

## 크로스 모델 리뷰

Codex. 정확성(업데이트 순서, 스테이지 전환, 너무 일찍 잠기거나 잠기지 않는 구간, 전환), 견고성, 보안 렌즈. 범위는 staged diff 의 `.cs` 파일.

결과는 `LGTM - no blockers` 였다.

## 남은 것

- 디렉터의 피드백을 기다린다
- 새가 먼저 구간에 들어가면 잠긴 동안 아기에게 돌아가지 못한다
