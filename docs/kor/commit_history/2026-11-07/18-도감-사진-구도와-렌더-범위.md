# 도감 사진의 빈 파티클 bounds를 구도에서 제외한다

## 왜 했나

절벽 메아리 도감 사진 프레임이 Web Development 기록에서 862ms, PhotoCamera 렌더 853.7ms, 불투명 렌더 792.1ms였다. 깊이 제한으로 하위 셰이더/Flush 비용은 확인할 수 없다.

## 확인한 원인과 수정

FrameSubject가 새 아래 빈 Ring/Sparkles ParticleSystemRenderer의 월드 원점 bounds까지 합쳤다. 실제 새 z239.6에서 PhotoCamera가 (135.79,138.47,-15.51)로 물러났다. 클로즈업이 아닌 넓은 숲을 그리는 구도 오류를 확인했다.

`Encyclopedia.cs`: 입자가 없는 ParticleSystemRenderer, 크기가 0인 bounds, disabled renderer는 구도 계산에서 제외한다. 살아있는 파티클과 다른 renderer 형식은 유지한다. 파티클/배경을 사진에서 지우지 않는다. 원경으로 잘못 찍던 사진이 의도한 클로즈업으로 바뀐다. 각도·해상도·far clip·촬영 시점은 그대로다. 새 상수, 런타임 생성/부트 코드, 씬/에셋 변경은 없다.

## 검증

- Unity script recompile 완료.
- Main은 저장하지 않고 Play Mode의 스테이지 3 끝에서 비교. 같은 순간/자세에서 수정 구도 거리 3.68m, 원본 구도 거리 297.53m.
- 수정 전체 TakePhoto 12.40/4.00/3.62ms, 원본 구도 렌더 7.75/7.33/9.04ms. 앞쪽은 첫 호출 초기화 포함, 뒤쪽은 워밍된 상태다. 이 수치로 웹의 854ms 해결을 단정하지 않는다.
- 640×360 사진을 직접 확인: 새의 클로즈업과 주변 풍경이 함께 보임. Play Mode 종료와 run in background 복구.
- 기존 웹 상세 프레임은 Profiler 버퍼에서 만료. 텍스트 원본은 보존.

## 크로스 모델 리뷰

Claude Sonnet 5.5.

- warn: Mesh/Skinned 전용 제한은 Sprite/Line/Trail을 제외한다 → 모든 renderer 형식 허용으로 해결.
- warn: zero bounds만 검사하면 빈 파티클의 stale bounds가 남을 수 있다 → particleCount==0 검사 추가.
- nit: disabled renderer 제외 → 유지. 동기 촬영 순간 안 보이는 조각은 구도를 늘리지 않아야 한다.
- nit: burst 사이 빈 입자는 구도에서 제외된다 → 수용. 실제 보이는 순간을 찍는 계약이며 살아있는 효과는 포함한다.
- 최종: `LGTM - no blockers`.

## 남은 검증

Release 웹 빌드/브라우저에서 메아리 첫 촬영 재측정 필요. 셰이더 첫 준비 비용까지 없어진 것으로 주장하지 않는다. 기존 사전 로딩/에셋 수정은 이 커밋에 포함하지 않는다.

## 되돌림 (사용자 피드백)

Release 빌드(오류 0, 71,173,883 bytes)에서 사용자가 랙이 더 심해졌다고 했다. 메아리 구간에 가기 전, 전에는 랙이 없던 곳에서도 프레임 드랍이 났다. 사용자 지시로 `Encyclopedia.cs`를 이 커밋 이전으로 되돌렸다.

이 코드는 이스터에그가 사진을 찍는 순간에만 돈다. 그래서 다른 구간의 드랍과 어떻게 이어지는지는 확인하지 못했다. 같은 조건에서 비교할 수 있도록 되돌린 코드로 다시 빌드한다. 구도 버그(빈 파티클 bounds 때문에 사진이 원경으로 찍힘)는 다시 남는다.
