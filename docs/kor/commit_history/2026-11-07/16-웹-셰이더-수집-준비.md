# 웹 셰이더 변형 수집: API 검증과 기록 빌드 준비

## 왜 했나

`order_from_director.md` C 단계. 게임 중 셰이더 첫 사용 멈춤을 로딩으로 옮긴다. 최종 목표는 실제 웹 플레이에서 수집한 ShaderVariantCollection과 Graphics Settings의 Preloaded Shaders 설정이며, 게임 코드 변경은 남기지 않는다.

## 검증

- Unity 6000.4.2f1, 현재 웹 그래픽 API는 OpenGLES3(WebGL2).
- 큐브 하나의 `Sam_Gsc_Test` 임시 씬으로 Development + ConnectWithProfiler 빌드 성공, 오류 0, 약 66초.
- Headless Chrome에서 `BeginTrace=True`, `isTracing=True`.
- 120프레임 뒤 변형 8개, graphics states 0개(WebGL) 수집. PlayerConnection 연결 True, SendToEditor True.
- `Assets/WebProbe.graphicsstate` 수신 후 에디터에서 variantCount=8 확인.
- Main 씬은 저장하지 않았다. 기존 변경 파일은 되돌리지 않았다.

## 진행 상태와 재개

- `Assets/GscWebProbe.cs`는 임시 기록기. BeforeSceneLoad에 시작하고 F8로 `WebGameplayTrace`를 에디터에 보낸다. Input System만 사용한다. 기록 빌드 후 파일과 meta를 지운다. 의도적으로 임시 기록 오브젝트를 만들며, 제품 코드가 아니다.
- `AgentScripts/BuildWebShaderTrace.cs`로 `Builds/WebShaderTrace` Development 빌드 진행 중. FMOD 로그는 빌드 동안만 ERROR로 낮추고 finally에서 복원한다.
- 사용자가 오프닝부터 엔딩까지 플레이 후 F8을 눌러야 전체 기록을 얻는다. 에디터와 Profiler를 열어 둔다.
- 임시 probe 씬, 기록기, probe 컬렉션, 빌더·검사 스크립트는 검증 후 제거한다. 기록용 코드는 커밋하지 않는다.
- 기록 후 GSC GetVariants의 shader / PassIdentifier / LocalKeyword를 SVC의 shader / PassType / keyword 문자열로 변환해야 한다. 패스 매핑은 아직 구현·검증하지 않았다. graphics state는 SVC로 옮겨지지 않지만 현재 대상은 WebGL이다.
- 다음 단계: 수집 → SVC 생성과 Preloaded Shaders 등록 → 교차 모델 리뷰 → Release 빌드 → 사용자 끊김·로딩 시간 확인.

## 참고

- 공식 6000.4 문서에서 WebGL, WebGPU 지원을 확인했다. WebGL warmup은 shader warmup으로 fallback한다.
- 조사 원문과 링크: 저장소 밖 `../opt_audit/gsc_research.md`.
- 사용한 임시 포트 8081 서버와 headless Chrome은 API 검증 후 종료했다.

## 빌드 완료

Development 기록 빌드 성공: 오류 0, 약 87초. http://localhost:8081/ 로 제공 중. 임시 런타임 기록기는 빌드 후 삭제했고, probe 씬과 보조 스크립트도 제거했다. probe 컬렉션 삭제는 도메인 리로드에 막혀 재확인이 필요하다. 전체 플레이 후 F8 수집을 기다린다.

## 수집과 사전 로딩 등록

사용자의 엔딩까지 플레이/F8 이후 WebGameplayTrace 91개 변형 수신. clean build의 IPreprocessShaders 패스 번호가 runtime GSC와 일치하지 않는 항목이 있어 정확 매핑은 포기했다(원인은 미확정). 캡처된 shader+keywords에 대해 SVC 생성자가 허용하는 모든 PassType을 넣는 보수적 상위집합으로 변환했다. 입력마다 최소 하나 이상 유효 패스 확인. 100개 허용 결과는 SVC에서 중복 제거되어 41 shaders / 64 variants. GraphicsSettings Preloaded Shaders 0→1, 기존 batch time limit -1 유지. 게임 런타임 코드 변경 없음.

Claude Sonnet 5.5 리뷰: blocker 없음. 상위집합 비용, batch -1의 로딩 중 blocking, 한 번의 플레이로 제한되는 커버리지는 수용하고 사용자 Release 로딩/끊김 확인 대상으로 남긴다. GUID 일치 확인. 리뷰 파일: ../opt_audit/reviewC.txt. 임시 trace 파일은 재생성 근거로 정리 필요.

Release BuildWeb.Run이 Unknown을 반환했으나 Editor.log에는 WebGL Bee 빌드가 계속 진행 중이다. 완료 판정 전 상태. 상태 조회 1회 실패도 발생. 최종 결과/브라우저 테스트 미확인, 커밋하지 않음. 임시 Assets/Editor 폴더, Assets/Resources 성능 테스트 파일, helper 정리 필요. 기존 파일 변경은 별도 보존.

## Release 결과

빌드 Succeeded, 71,164,899 bytes, 7분 18.65초. totalErrors=1은 빌드 중 내가 호출한 존재하지 않는 editor.dialog 조회 오류가 집계된 것이며, BuildReport의 유일한 Error 메시지로 확인했다. 경고 33개(기존 코드·셰이더 경고 및 WebGL embedded video 미지원 등). 실제 제품 빌드 실패는 아니다. http://localhost:8082/ 에서 Release 확인 가능. 다운로드/로딩 시간 및 끊김 개선은 사용자 확인 대기. trace는 Assets/04_Data로 이동했고 임시 Editor 폴더와 검사/매핑 스크립트는 삭제했다. 재생성 도구 BuildWebShaderWarmup.cs는 유지. 아직 커밋하지 않았다.

## Release 사용자 피드백과 추가 측정

사용자: 끊김은 줄었으나 구름, 계절 전환, 안개 진입, 절벽 메아리 이스터에그, 엔딩 중간중간에서 남는다. 시작 로딩은 거의 늘지 않았다. 소리 첫 로딩이 원인일 수도 있어 종합 측정을 요청했다.

사전 로딩이 적용된 Development+ConnectWithProfiler 빌드를 기존 WebProfile.Build로 Builds/WebGLDev에 생성 중. Release는 그대로 유지. FMOD 로그는 기존 측정 도구처럼 빌드 동안만 ERROR. Deep Profiling이나 게임 코드 계측은 추가하지 않았다. 다음: 빌드 결과 확인, WebGLDev 서버 시작, WebProfile.Start로 프레임/50ms 이상 트리 기록, 사용자 전체 플레이와 종료 신호 후 Stop. FMOD 호출/로딩, Shader.CreateGPUProgram, GC, 계절 작업을 비교하고 샘플에 보이지 않는 비용은 추정으로 단정하지 않는다. 사용량 5시간 70%, 주간 30%, 컨텍스트 약 46.5%이며 빌드/기록 준비는 진행 가능으로 판단했다.
