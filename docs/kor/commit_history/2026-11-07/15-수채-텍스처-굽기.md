# 수채 텍스처 3장을 에디터에서 굽는다 (ADR 0039)

## 왜 했나

`WatercolorManager` 가 바닥 무늬와 연필 선 텍스처(512, 밉맵)를 씬을 불러오기 전에(`BeforeSceneLoad`), 붓 자국 텍스처를 처음 쓸 때(컷신 도중) C# 루프로 그렸다. 메인 스레드에서 시간이 들고 임시 배열 약 7 MB 가 웹 힙을 키운다. `order_from_director.md` 5번이다. 사용자가 바로 되돌릴 수 있게 따로 커밋하라고 했다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 세 텍스처를 그리는 코드를 `Make*Texture` 함수로 뺐다. 쓸 때는 구운 에셋이 있으면 그것을, 없으면 예전처럼 그린다. 연필 텍스처는 룩의 연필 설정 다섯 개가 구울 때와 같을 때만 구운 것을 쓴다. 설정이 다르면(에디터에서 룩을 조절할 때) 따로 둔 텍스처에 그리고, 구운 에셋에는 그리지 않는다 | `Assets/02_Scripts/Rendering/WatercolorManager.cs` |
| 구운 텍스처와 연필 설정을 담는 ScriptableObject | `Assets/02_Scripts/Rendering/WatercolorTextures.cs` |
| 굽기 도구. 모든 `WatercolorLook` 의 연필 설정이 같은지 확인하고, 텍스처를 하위 에셋으로 저장한 뒤 읽기 불가로 둔다 | `AgentScripts/BakeWatercolorTextures.cs` |
| 구운 에셋 | `Assets/04_Data/Resources/WatercolorTextures.asset` |

되돌리려면 이 커밋을 되돌리거나 에셋만 지우면 된다. 에셋이 없으면 예전처럼 그린다.

## 검증

| 무엇 | 결과 |
|------|------|
| 굽기 | 룩 8개의 연필 설정이 하나 `(0.184, 1.87, 4.03, 0.87, 20.7)`. 바닥 무늬와 연필은 RGBA32·리니어·밉 10·Repeat·Trilinear, 붓 자국은 RGBA32·리니어·밉 없음·Repeat·Bilinear. 예전 런타임 텍스처와 같다. 모두 읽기 불가 |
| Play Mode | `_WC_FloorPattern`, `_WC_PencilStrokes` 전역 텍스처가 구운 에셋의 것이다 |
| 컴파일 | 오류 0 |

## 크로스 모델 리뷰

GPT-6.1 Sol. 렌즈: 텍스처 설정이 예전과 같은지, 읽기 가능 여부, 제자리 다시 그리기, 정적 캐시와 도메인 리로드, 메모리.

| 지적 | 처리 |
|------|------|
| warn. 설정을 바꿨다가 구운 설정으로 돌아오면 그린 텍스처를 버려 쌓인다 | **반영.** 그린 텍스처는 `s_PencilDrawn` 에 두고 다시 쓴다 |
| warn. 에셋이 없을 때 한 번 찾은 결과가 남아, 같은 에디터 세션에서 구운 에셋을 쓰지 못한다 | **반영.** 없는 동안에는 매번 다시 찾는다 |
| warn. 도메인 리로드를 끈 플레이에서는 굽기 전에 그린 텍스처가 캐시에 남는다 (확인 리뷰) | **기각.** 이 프로젝트는 플레이할 때 도메인을 다시 불러온다(`EnterPlayModeOptions: 0`). 에디터 모드에서 구운 직후에만 리로드 전까지 그린 것을 쓰고, 모습은 같다 |
