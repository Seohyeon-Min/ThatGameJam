# 웹 셰이더 첫 사용을 게임 첫 프레임에 미리 그린다 (ADR 0040)

## 왜 했나

셰이더 사전 로딩 뒤에도 웹 빌드의 인트로 비행 구간에서 가끔 끊겼다. 사용자는 구름 퍼프를 줄여야 하는지 물었다. 측정 기록(`Builds/profile/spikes_174526.txt`)에서 그 구간 평소 프레임은 중간값 약 9 ms 였다. 50 ms 를 넘은 프레임은 거의 모두 셰이더 첫 사용(`ApplyShader`, `CreateGPUProgram`, 64~705 ms)이었다. 그래서 퍼프 수가 아니라 첫 사용을 앞으로 옮겼다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 게임 첫 3프레임 동안 씬의 머티리얼 141개를 `Graphics.RenderMesh` 로 한 번씩 그린다. 카메라 앞 1e-5 배라 보이지 않는다. 레이어, 렌더링 레이어, 그림자 설정은 원래 렌더러 것을 쓴다. 끝나면 스스로 꺼진다 | `Assets/02_Scripts/Rendering/ShaderPrewarm.cs`, `Main.unity` 의 `01_SYSTEM/ShaderPrewarm` |
| 목록 빌더. 씬 렌더러(꺼진 것 포함)의 머티리얼 109개, 스크립트만 참조하고 렌더러가 쓰는 셰이더를 가진 머티리얼 32개. 저장되지 않는 메시는 쿼드로 대신한다 | `AgentScripts/BuildShaderPrewarm.cs` |

## 중요한 결정

- [ADR 0040](../../decisions/0040-웹-셰이더-첫-사용은-첫-프레임에-그려-둔다.md). AGENTS.md 의 시작 코드 금지 규칙의 예외로 사용자가 허락했다. 구름 퍼프는 줄이지 않는다.
- Main.unity 는 먼저 다시 저장만 한 커밋(`2c68a8b`)을 따로 만들었다. 이번 씬 diff 는 약 1,000줄이다. WindingWater 메시 2개는 저장할 때마다 ID 만 바뀐다.
