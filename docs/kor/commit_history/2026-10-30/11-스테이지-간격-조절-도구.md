# 스테이지 간격 조절 인스펙터 도구

## 왜 했나

저장소 소유자 제안: "스테이지간의 space 조절기 하나 만드는거 어떨까싶어." 바로 앞(10번 기록)에서 Intro→Stage1 간격을 스크립트로 수작업 조정했는데, 같은 걸 매번 CLI로 손으로 할 게 아니라 인스펙터에서 바로 쓸 수 있는 도구로 만들어달라는 요청.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| `Stage.AdjustSpacing(float deltaZ, bool cascadeToLaterStages)`: 이 스테이지의 트랜스폼(그 아래 전부 포함 — 경로, 시작점, 나무 생성기)과 `area`(새가 나는 범위)를 +Z로 `deltaZ`만큼 민다. `cascadeToLaterStages`가 켜져 있으면 `GameFlow`에 등록된 순서대로 이 스테이지 **뒤에 오는** 모든 스테이지에도 같은 양을 적용(그 스테이지들끼리의 기존 간격은 그대로 유지하면서 이 경계의 간격만 바뀜). 꺼져 있으면 바로 앞 경계의 간격만 바뀜(10번 기록에서 Intro에 썼던 것과 동일) | `Assets/02_Scripts/Flow/Stage.cs` (`#if UNITY_EDITOR` 블록, `TreeGenerator.Generate/Clear`와 같은 패턴) |
| `GameFlow.Stages` 읽기 전용 접근자 추가(기존 `stages` 배열을 캐스케이드용으로 읽을 수 있게) | `Assets/02_Scripts/Flow/GameFlow.cs` |
| 인스펙터 버튼: `Shift Along Road (Z)` 값 입력 + `Also shift every later stage` 토글 + `Apply` 버튼 | `Assets/02_Scripts/Flow/Editor/StageEditor.cs`(새 파일, `TreeGeneratorEditor`/`SeasonEditor`와 같은 UIElements 패턴) |

## 중요한 결정

- 지형(시내, 통나무가 걸쳐 있는 지점 등 `World` 아래 공유 지형)은 건드리지 않는다. `Stage`가 소유한 것(그 자식들, `area`)만 민다 — 10번 기록에서 "지형 수정은 범위 밖"이라고 판단한 것과 같은 경계.
- `cascadeToLaterStages`를 켜면 "이 스테이지 뒤"를 `GameFlow.stages` 배열의 **저작 순서**로 찾는다(씬 계층 구조상의 순서나 트랜스폼 상 Z값이 아니라). 썬 하이어라키 순서는 신뢰할 수 없어서.
- 한 번에 한 경계만 조정하는 걸 기본으로 했다(캐스케이드 꺼짐 = 바로 앞 간격만). 여러 경계를 한 번에 조정하고 싶으면 앞에서부터 순서대로 여러 번 누르면 된다 — 한 번의 조작으로 전체 체인을 재배치하는 건 지금은 안 만들었다(필요해지면 추가).
- Undo를 지원한다(`Undo.RecordObject`로 트랜스폼과 `area` 둘 다 기록) — 값을 잘못 넣어도 Ctrl+Z로 되돌릴 수 있다.

## 검증

| 무엇 | 결과 |
|------|------|
| 컴파일 | `script recompile` → `completed`, 에러 0 |

| `Stage1.AdjustSpacing(3, true)` 호출 후 되돌리기(`-3`) | `Stage1`과 `Stage2` 둘 다 같이 이동, 되돌린 뒤 둘 다 정확히 원래 값(0)으로 복귀 |
| 테스트 왕복 후 `git diff` | `Main.unity`는 변경 없음(부동소수점 드리프트도 없이 정확히 원상태) — 스크립트 3개(`Stage.cs`, `GameFlow.cs`, 새 `StageEditor.cs`)만 변경 |
| 콘솔 | 에러 0 |

## 남은 것

- 여러 경계를 한 번에 재배치하는 일괄 도구는 안 만들었다(필요하면 추가).
- 인스펙터에서 직접 눌러보는 건(스크립트 호출이 아니라 실제 버튼 클릭) 아직 안 해봤다 — UIElements 바인딩 자체는 기존 패턴 그대로라 문제없을 걸로 보이지만, 직접 눌러서 확인은 필요.
