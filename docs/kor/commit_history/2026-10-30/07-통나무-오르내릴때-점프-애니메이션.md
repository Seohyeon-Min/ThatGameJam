# 통나무(균형대)에 오르내릴 때 Girl_Jump 재생

## 왜 했나

저장소 소유자 제안: "아이가 나무에 오르고 내릴 때 점프 애니메이션을 재생하는 건 어때." 지난 10-29 세션에서 `Girl_Jump`를 애니메이터 상태까지만 만들어두고 "어디서 쓸지 결정 안 됨(통나무에서 내려올 때, 작은 장애물, 또는 보류)"로 남겨뒀던 바로 그 자리.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| `jumpClip` 필드(`Girl_Jump`, 1.5초) 추가. `PlayJump()` 코루틴: 제자리에 서서(`StandStill`) Jump 상태로 크로스페이드하고 클립 길이만큼 기다림 | `Baby.cs` |
| 통나무 구간 시작(`BalanceBeamStart`)·끝(`BalanceBeamEnd`) 도달 시, 그리고 쓰러지는 고목(`LeaningLog`)이 열려 막 건너기 시작할 때, 각각 `BalanceWalk`/`Walk`로 바뀌기 직전에 `yield return PlayJump()` 삽입 | `Baby.cs` (`WakeAndWalk`) |
| 씬의 `Baby` 컴포넌트 `jumpClip` 필드에 `Girl_Jump` 클립 연결 | `Sam_Test.unity` |

## 중요한 결정

- 세 지점(통나무 시작/끝, LeaningLog) 전부 같은 코루틴을 공유하게 했다. 셋 다 "balance beam 상태가 바뀌기 직전, 제자리에서"라는 같은 조건이라 따로 만들 이유가 없었다.
- Jump 재생 중엔 `StandStill()`로 제자리에 세워둔다. 이동(`transform.position`)과 애니메이션을 분리해 둔 기존 구조(StepToward는 그대로, 시각 효과만 얹는다) 원칙을 그대로 따랐다 — Jump 클립 자체에 도약하는 모양이 있어도 실제 위치는 WalkTo가 이미 그 지점에 도착시켜 놓은 자리에서 제자리 홉으로 보인다.
- Animator Controller의 `Jump` 상태는 10-29에 이미 전환 없이(진입·이탈 전부 스크립트 `CrossFade`) 만들어져 있어서 컨트롤러는 손대지 않았다.

## 남은 것

- Jump 모션 자체가 실제로 "오르내리는" 느낌으로 보이는지(웅크림·도약·착지 타이밍이 제자리 재생과 자연스럽게 어울리는지)는 화면으로 직접 못 봤다 — 애니메이터 상태 전환 로그로만 확인함.
