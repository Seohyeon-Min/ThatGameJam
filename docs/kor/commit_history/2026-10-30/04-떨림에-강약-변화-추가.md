# 떨림이 일정한 세기로 계속되지 않고 강약이 오르내리게 함

## 왜 했나

03에서 떨림 세기 자체는 낮췄지만, 저장소 소유자가 "일정하게 떨리지 말고 랜덤하게 떨면 좋겠다"고 요청. 기존 코드는 고정된 각도·빈도로 Perlin 노이즈를 돌리기만 해서, 세기는 일정하고 방향만 흔들리는 "일정한 웅웅거림"이었다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 떨림 각도에 느리게 변하는 "강도 포락선"(intensity envelope)을 곱함. 별도의 느린 Perlin 채널로 0(거의 안 떪)~2×`babyShiverIntensityVariation`(더 세게 떪) 사이를 불규칙하게 오르내림 | `Baby.cs` (`Update`) |
| 포락선 변동 폭(`babyShiverIntensityVariation`, 0~1)과 변하는 속도(`babyShiverIntensityFrequency`, 느림) 튜닝값 | `GameTuning.cs`, `GameTuning.asset`(지난번 교훈대로 에셋에도 명시적으로 적음) |

## 중요한 결정

- 완전히 랜덤(매 프레임 무작위)하게 만들면 지글거리는 노이즈처럼 보여서 오히려 더 어색해진다. 기존 코드 전체에서 쓰는 패턴(Perlin 노이즈로 부드럽게 변화)을 그대로 따라, 떨림 자체의 빠른 흔들림(3.5Hz)은 유지하고 그 위에 훨씬 느린(0.35Hz, 약 3초 주기) 강도 채널을 곱하는 방식을 썼다 — "지금은 좀 심하게 떨다가 잠깐 잠잠해지는" 느낌.
- `babyShiverIntensityVariation = 0.7`로 잡아서, 강도가 완전히 0까지 떨어지는 순간(거의 안 떪)과 평소보다 1.7배 센 순간을 둘 다 오가게 했다. 완전히 0을 막진 않았다 — 이따금 떨림이 거의 멎는 순간이 있는 게 오히려 "규칙적이지 않다"는 느낌을 더 준다고 판단.

## 검증

| 무엇 | 결과 |
|------|------|
| `Baby.cs`/`GameTuning.cs` 컴파일 | `script recompile` → `completed`, 에러 0 |
| `.asset` 강제 재임포트 후 `GameTuning.Current`로 새 필드 값 확인 | `0.7`/`0.35`로 정상 반영 |
| Play Mode에서 1초 간격으로 12회, `modelBaseRotation`과 실제 모델 회전 사이의 각도 차이(=그 순간 떨림 크기)를 직접 측정 | 0.000°(거의 안 떪)부터 0.638°(세게 떪)까지 시간에 따라 오르내리는 것을 확인. 고정된 한 값 근처에서만 맴돌지 않음 |

## 남은 것

- 강약 변화의 체감(0.35Hz 주기, 0~0.7 변동폭)이 실제로 "자연스러운 랜덤함"으로 보이는지는 여전히 직접 플레이하면서 봐야 한다.
