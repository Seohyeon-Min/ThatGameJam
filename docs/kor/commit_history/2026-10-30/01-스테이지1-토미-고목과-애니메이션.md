# 스테이지 1의 고목을 토미의 모델과 애니메이션으로 교체

## 왜 했나

사용자가 토미 브랜치의 물 건너기용 고목 모델과 애니메이션을 스테이지 1에 넣어 달라고 했다.
`origin/Tommy`의 `c5582ad`에서 추가된 `broken tree.fbx`와 원본 메타데이터를 가져왔다. 다른 브랜치 변경은 합치지 않았다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 첫 번째 다리는 `break` 마지막 자세를 고정. 모델에 포함된 그루터기도 사용 | `Sam_Test`의 `Stage1/FallenLog_Art` |
| 두 번째 고목은 `idle`(7.5초, 반복) → 해결 시 `break`(약 3.292초, 1회). 마지막 자세 유지 | `BrokenTree_Animator.controller`, `LeaningLog.cs` |
| 새를 쓰러지기 시작할 때 놓아 주고, 클립이 끝난 뒤 길을 연다. 30초 자연 해결과 도움 반응은 유지 | `LeaningLog.cs` |
| 모델은 원래 −Z로 쓰러지므로 Y축 180도 회전. 첫 다리 배율 2.2, 두 번째 배율 1.4. 밑동 Z는 각각 7, 19.1. 클릭용 메시 콜라이더와 움직이는 줄기 꼭대기의 앉는 자리 | `BuildSamTestScene.cs`의 `SetupStage1Logs` |
| 경로 높이를 쓰러진 메시에서 측정. 고목 구간은 0.1m 간격, 주변 ±0.1m 표면도 확인하고 최대 상승 기울기 1.5로 밑동을 넘도록 연결. 정지점 Z 19 → 18 | 같은 빌더와 씬의 `BabyRoute` |
| 전체 씬 재생성 없이 스테이지1의 두 모델·경로만 교체하는 진입점. 전체 빌더도 같은 함수를 사용 | `SetupStage1Logs.Run`, `BuildStage1` |
| 실제 Play Mode에서 가상 마우스 클릭과 자연 해결을 검사 | `AgentScripts/VerifyStage1Logs.cs` |

## 검증

| 무엇 | 결과 |
|------|------|
| C# 재컴파일, 전체 빌더 dry run | 통과 |
| 실제 프레임 진행 + 가상 마우스로 고목 클릭 | `idle` → 새 착지 → 새 놓아주기 → `break` → 종료 뒤 길 열림 통과 |
| 아기 도착 뒤 30초 자연 해결 | 대기, 타이머 시작, `break`, 종료 뒤 길 열림, 최종 자세 유지 통과 |
| 두 해결 방식의 아기 경로 | 두 고목을 건너 스테이지2로 진행 통과 |
| 물 구간 경로와 메시 교차 | 두 물 구간에서 메시 누락 0 |
| Unity 콘솔 | 컴파일·실행 에러 0 |

## 참고

- 모델의 원래 어두운 갈색 머티리얼은 그대로 사용했다. 텍스처가 빠진 것이 아니라 원본 단색이다.
- 기존 눈, 새·소녀 컨트롤러와 다른 미커밋 변경은 수정하지 않았다. 테스트 후 Play Mode와 run in background를 껐다.
- 원본 애니메이션에는 밑동 갈라짐과 쓰러짐이 있지만 별도 눈 덩어리·소리는 없다. 이번에는 새로 만들지 않았다.

## 크로스 모델 리뷰

Claude Sonnet 4.6. 정확성·견고성·경로/애니메이션 렌즈.

| 등급 | 지적 | 처리 |
|------|------|------|
| blocker | `Tube` 자식 이름이 다르면 null 접근 | **기각.** 가져온 고정 FBX의 실제 자식 `Tube`와 MeshFilter를 에디터에서 확인했다. 이 빌더는 그 모델 전용이며 모델 변경 호환은 범위 밖이다. |
| warn | `idle`/`break` 이름이 다르면 사전 인덱스 실패 | **기각.** 원본 메타데이터 및 임포트된 두 클립을 확인했다. 없는 이름은 KeyNotFoundException으로 중단되며 조용히 잘못 생성되지 않는다. |
| warn | 자식 콜라이더 클릭 시 루트 Perchable을 못 찾을 가능성 | **기각.** `BirdController.PerchableAt`은 이미 `hit.collider.GetComponentInParent<Perchable>()`를 쓴다. 실제 가상 마우스 클릭·착지·해결 테스트도 통과했다. |
| nit | Animator speed를 나중에 바꾸면 대기 시간 불일치 | **기각.** 생성한 Animator와 Break 상태의 속도는 1이며 이를 바꾸는 코드가 없다. 미래의 속도 변경은 이번 범위 밖이다. |
| nit | break 클립이 반복이면 쓰러짐 재시작 | **기각.** 원본 메타데이터의 `break.loopTime=0`을 확인했고, 실제 Play Mode에서 최종 자세 유지도 검사했다. |
| nit | 모델이 물을 덮는지 빌더 검증 없음 | **기각.** 별도 에디터 검증에서 두 물 구간을 촘촘히 검사해 메시 교차 누락 0, 두 해결 방식에서 스테이지2 도착을 확인했다. 모델 전용 빌더에 같은 테스트를 중복 구현하지 않았다. |

해결하지 않은 결함은 없다. Claude CLI 리뷰는 로그인되지 않아 실행되지 않았고, 위 별도 모델 리뷰로 대체했다.
