# 새가 좌우로 돌 때 기울어지는 방향이 반대였던 것 수정

## 왜 했나

저장소 소유자가 직접 플레이하다 발견: "새 좌우회전 tilt 앵글이 반대임! 오른쪽으로 회전할 때 오른쪽 날개가 아래로 내려와야 함." 지금은 반대로 내려가고 있었다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| `Face()`의 뱅크 목표각 계산에서 `-turnRate`를 `turnRate`로(부호 반전 제거) | `Assets/02_Scripts/Bird/BirdController.cs` |

## 중요한 결정

- 부호를 머리로 추론하지 않고 Play Mode에서 직접 확인했다. 일시정지 상태에서 `Bank()`를 리플렉션으로 호출하면 `Time.deltaTime=0`이라 `MoveTowards`가 전혀 안 움직이는 함정이 있어서, `bankAngle` 필드와 `visualRoot.localRotation`을 직접 설정해 `+60°`를 강제로 만들고 뒤에서 본 스크린샷으로 "오른쪽(화면 기준, 카메라가 새 뒤에서 같은 방향을 보고 있으니 새의 실제 오른쪽과 일치)이 아래로 내려간다"를 먼저 확인했다. 그다음 실제 `Face(bird.transform.right)`를 호출해 오른쪽으로 트는 입력이 `turnRate` 양수·`facingYaw` 증가를 만든다는 것도 같이 확인하고 나서 부호를 맞췄다.
- 고치는 김에 왜 `turnRate`와 `bankAngle`의 부호가 같아야 하는지 주석으로 남겨, 다음에 또 헷갈리지 않게 했다.

## 검증

| 무엇 | 결과 |
|------|------|
| `BirdController.cs` 컴파일 | `script recompile` → `completed`, 에러 0 |
| 수정 전: `bankAngle`을 직접 `+60`으로 설정하고 새 뒤에서 캡처 | 화면 기준 오른쪽(새의 실제 오른쪽)이 아래로 내려감 확인 → 양수 `bankAngle` = 오른쪽 날개 아래, 라는 매핑을 먼저 확정 |
| 수정 후: 실제 `Face(bird.transform.right)`를 15회 호출(오른쪽으로 트는 입력 시뮬레이션) | `facingYaw`가 0→6°로 증가(오른쪽으로 돎 확인), `bankAngle`이 양수(+7)로 나옴 → "오른쪽으로 틀면 양수 뱅크(=오른쪽 날개 아래)"가 이제 성립 |
| `git status` | `BirdController.cs` 한 줄만 변경 |

## 남은 것

- 실제 플레이에서 마우스로 새를 몰아 좌우로 틀며 체감하는 뱅크 느낌(속도·최대각)은 이번엔 안 건드렸다. 저장소 소유자가 "방향이 반대다"라고만 했지 세기에 대한 불만은 없었어서 `birdBankSensitivity`/`birdMaxBankAngle`/`birdBankSpeed` 수치는 그대로 뒀다.
