# 아기 떨림이 과하던 문제, 카메라 페이드가 LeaningLog를 지우던 문제 수정

## 왜 했나

저장소 소유자가 직접 본 문제 둘을 보고: (1) 아기가 "사시나무 떨듯" 떤다, 혹시 이번 point-of-interest 작업 때문인가. (2) (전해 들은 얘기로) 카메라 페이드가 기믹인 고목(LeaningLog)도 지워버린다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 추위 떨림 세기·빈도를 낮춤(2.5°/9Hz → 0.8°/3.5Hz). 두 축에 동시에 걸려 있던 게 세고 빨라서 몸 전체가 인형처럼 버징하는 것처럼 보였음 | `GameTuning.cs` |
| `Perchable`에 `alwaysExempt` 옵션 추가. 켜져 있으면 새가 앉아있지 않아도 항상 카메라 페이드 면제. 장식용 길가 나무 가지(`idleSpot`)는 그대로 배경처럼 페이드되게 두고, LeaningLog의 `Trunk`(플레이어가 상호작용해야 하는 기믹)만 켬 | `Perchable.cs`, `Sam_Test.unity`(LeaningLog/Trunk의 `alwaysExempt: 1`) |

## 중요한 결정

- 떨림은 이번 point-of-interest(glance) 작업과 무관하다. glance는 머리뼈만, 그것도 4~9초에 한 번 1.5초만 움직인다. 떨림은 지난 세션(`04a0531 baby movement`, 내가 참여하기 전)에 들어간 `Baby.cs`의 `Update()` 전신 떨림 코드였다. 사용자에게도 이 점을 분명히 설명함.
- 씬 전체를 뒤져서 `Perchable` 인스턴스를 전부 확인한 결과, "장치"(기믹)에 해당하는 건 LeaningLog의 `Trunk` 하나뿐이고 나머지는 전부 길가 나무의 장식용 유휴 쉼터(`idleSpot=true`)였다. 그래서 `alwaysExempt`를 일괄 적용하지 않고 LeaningLog에만 켰다 — 길가 나무 가지는 배경처럼 자연스럽게 페이드되는 게 의도대로 맞다.
- **중요한 함정 발견:** `GameTuning.asset`에는 어제~오늘 추가한 새 튜닝 필드(`babyShiver*`, `babyGaze*`, `babyWander*` 등)가 전혀 저장돼 있지 않았다 — 전부 C# 기본값에 암묵적으로 의존하고 있었다. 이 상태에서 코드 기본값을 바꾸고 재컴파일해도, **이미 메모리에 한 번 로드된 에디터에서는 반영되지 않는다**(네이티브 오브젝트가 이미 구 기본값으로 역직렬화되어 있어서, 도메인 리로드가 그 값을 새 기본값으로 안 바꿔줌). 직접 `.asset` 파일에 값을 명시적으로 적어넣고 `AssetDatabase.ImportAsset(ForceUpdate)`로 강제 재임포트해야 실제로 반영됐다. 앞으로 `GameTuning`에 새 필드를 추가하면 **에셋 파일에도 명시적으로 값을 적어야** 한다는 걸 확인함.

## 검증

| 무엇 | 결과 |
|------|------|
| `GameTuning.cs`/`Perchable.cs` 컴파일 | `script recompile` → `completed`, 에러 0 |
| LeaningLog `Trunk`에 `alwaysExempt=true` 설정 후 Play Mode에서 렌더러의 `_CameraFadeExempt` 셰이더 프로퍼티 직접 조회 | `1`로 확인(새가 안 앉아있어도 면제됨) |
| `.asset` 강제 재임포트 후 `GameTuning.Current.babyShiverAngle/Frequency` 조회 | `0.8`/`3.5`로 정상 반영 확인(재임포트 전엔 `2.5`/`9`로 나와서 위 함정을 발견함) |
| `git diff` | `Sam_Test.unity`는 `alwaysExempt: 1` 한 줄만 변경 — 의도한 것만 바뀜 확인 |

## 남은 것

- 떨림 수치(0.8°/3.5Hz)는 "버징처럼 안 보이게" 낮춘 추정치다. 실제 화면으로 "이 정도면 자연스러운 추위 떨림"인지는 아직 못 봤다 — 플레이해보고 추가 조정 필요할 수 있음.
- 2-2(토끼 가족), 3-1~3-3(안개, 구름) 등 아직 안 만들어진 스테이지의 기믹에도 똑같은 카메라 페이드 문제가 생길 수 있다. 그 기믹들을 만들 때 `Perchable.alwaysExempt`(또는 Perchable이 아닌 기믹이면 비슷한 처리)를 켜야 한다는 걸 기억해 둘 것.
