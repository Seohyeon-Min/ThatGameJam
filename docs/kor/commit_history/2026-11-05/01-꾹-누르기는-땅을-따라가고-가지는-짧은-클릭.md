# 꾹 누르면 포인터 아래 땅을 따라가고, 가지는 짧게 클릭해야 앉는다 (ADR 0030)

## 왜 했나

디렉터의 지시 1번(`order_from_director.md`). 꾹 눌러 앞으로 갈 때 새가 긴가민가하며 간다. 원인을 Play Mode 에서 잰 결과 누르고 있는 동안 포인터가 길가 나무의 앉는 자리 위를 지나면 목표점이 그 나무로 튀었다. 측정과 결정은 [ADR 0030](../../decisions/0030-꾹-누르기는-땅을-따라가고-가지는-짧은-클릭으로.md) 에 있다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 누르고 따라가는 목표점은 포인터 아래의 땅(`Ground`, `ClickPlane`)만 본다. 가지는 앉기 판정에만 쓴다 | `BirdController.cs` `Update` |
| 가지 위에서 누르면 `pressedPerch` 로 기다린다. 0.2초 안에 떼면 `ClickPerch`, 더 누르면 그때의 땅으로 `Click` 하고 따라간다. 컷신 고정과 사전이 열릴 때는 기다림을 지운다 | `BirdController.cs` `Update`, `ClickPerch`, `Click` |
| 앉기 커서는 버튼을 누르고 있지 않을 때나, 가지 위에서 막 누른 동안에만 보인다 | `BirdController.cs` `Update` |
| `Click` 을 가지 클릭(`ClickPerch`)과 땅 클릭(`Click`)으로 나누고, 걷는 중 다시 뛰기(`HopAgain`)를 땅 클릭 안으로 옮겼다 | `BirdController.cs` |
| `birdPerchClickSeconds` = 0.2 | `GameTuning.cs` |
| 새 조작 설명 | `docs/kor/implementation_plan.md`, `docs/eng/implementation_plan.md` |

`GameTuning.asset` 은 고치지 않았다. 새 필드는 에셋에 값이 없어서 코드의 기본값 0.2 를 쓴다. 에디터에서 에셋을 다음에 저장할 때 값이 들어간다.

## 검증

Main 씬 Play Mode. 인트로를 건너뛰고 1스테이지에서 가상 마우스(`InputSystem.AddDevice`)로 눌렀다. 프레임마다 새의 상태, 목표점, 포인터 아래 땅의 점을 기록했다.

| 무엇 | 결과 |
|------|------|
| 고치기 전, 새 오른쪽 위 한 점을 7초 누름 | 목표점이 33% 의 프레임에서 나무 위. 5~12 m 튐 7번. 가는 방향 −18° ~ +31° |
| 고친 뒤, 같은 방식으로 4초 누름 | 목표점과 포인터 아래 땅의 차이 최대 0.62 m(기록이 한 프레임 늦어서). 가는 방향 −6.8° ~ +2.3°. 범위 끝(z 8.35)에서 가지에 앉아 고개 젓기(ADR 0016, 그대로) |
| 가지 위에서 누르고 0.1초 뒤 뗌 | 0.04초 기다렸다가 뗄 때 그 가지로 `ToPerch`, 착지 |
| 가지 위에서 누르고 2초 동안 누름 | 0.2초 뒤 `Flying`, `following` 켜짐, 목표점은 포인터 아래 땅(−11.26, 11.59). 그 가지에는 앉지 않음 |
| 컴파일 | 오류 0. 경고는 원래 있던 다른 파일의 것뿐 |

에디터가 포커스를 갖지 않아 가상 마우스의 입력이 게임에 가지 않았다. 그래서 Play Mode 안에서만 Input System 설정 두 개(`backgroundBehavior` = `IgnoreFocus`, `editorInputBehaviorInPlayMode` = `AllDeviceInputAlwaysGoesToGameView`)를 바꾸고 실제 키보드와 마우스를 껐다. 끝나고 설정을 되돌리고, 가상 마우스를 지우고, 실제 장치를 켜고, Run In Background 를 껐다.

시행착오. 처음에는 설정 복사본을 만들어 `InputSystem.settings` 에 넣었다. Play Mode 를 다시 시작할 때 도메인 리로드로 그 복사본이 사라져 Input System 초기화가 계속 실패했다. 숨은 상태 객체(`InputSystemObject`)의 설정 참조를 원래 설정으로 되돌리고 스크립트를 다시 불러 고쳤다. 그 뒤로는 Play Mode 에 들어간 다음 원래 설정 객체의 값을 바꾸고(`InputManager.ApplySettings`), Play Mode 를 나가기 전에 되돌렸다.
