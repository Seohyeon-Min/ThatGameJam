# 새의 범위 1.5배, 인트로 출발점 뒤 나무, 눈의 바람 (ADR 0021)

## 왜 했나

사용자 지시. 눈의 바람을 x 0.5, z −5 로. 인트로 출발점 왼쪽에도 나무를. 새의 범위를 좌우 1.5배로.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 새의 범위 x ±13 → ±19.5 | 빌더 `BirdAreaHalfWidth` |
| 인트로의 숲을 카메라가 볼 수 있는 곳까지 뒤로 늘리고, 출발점 3 m 뒤부터 길 위에도 나무(`TreesBehindTheStart`). 나무 280 → 345 그루 | 빌더 `BuildWorld` |
| 눈의 바람 (0.5, −5). 상자를 바람이 불어오는 쪽으로 옮겼다(가장 느린, 가장 빠른 눈송이 둘 다). 1 m² 당 1.5 → 1.0, 수명 11 → 9.8 초 | 빌더 `SnowWind`, `Snow` |
| 결정과 계획 | ADR 0021, `implementation_plan.md` 3.3, 4.1, 4.6, 4.9, 6.1 |

## 검증

| 무엇 | 결과 |
|------|------|
| 빌더 `Build` | 에러 0. 나무 345 그루, 눈 상자 59 × 73 m, 초당 약 4350 개 |
| Play: 시작 화면 | 바람에 날리는 눈이 화면 전체에 내린다. 출발점 왼쪽(뒤)에 숲이 있다. 눈송이 약 4.3 만 개, 에디터 약 130 FPS |
| 새를 x −30 으로 옮김 | x −17.7 에서 멈췄다(범위 −19.5 와 화면 여유 안) |
| 새를 (−19.5, −26), (19.5, −5) 로 | 눈이 화면을 덮는다. 범위 끝에서는 숲 너머의 눈밭이 보인다 |

## 크로스 모델 리뷰

Codex. 정확성(바람에 밀리는 거리, 상자 계산, 나무 범위), 보안, 견고성 렌즈. 범위는 빌더의 diff.

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | 상자를 평균 낙하 속도로만 계산해, 느린 눈송이가 약 5.5 m 더 밀려 화면 가장자리를 덮지 못한다 | **반영.** 가장 느린 것과 가장 빠른 것의 밀리는 거리를 둘 다 넣어 상자를 잡는다 |

다시 돌린 리뷰는 `LGTM - no blockers` 였다.

## 남은 것

- 눈송이 약 4.3 만 개의 웹 성능
- 새가 범위 끝에 가면 숲(x ±21.4) 너머가 보인다. 숲을 넓힐지는 사용자가 정한다
