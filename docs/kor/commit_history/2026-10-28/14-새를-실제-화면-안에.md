# 새를 실제 화면 안에 두고, 카메라 구간은 맵 가장자리 가까이에서 풀리게 (ADR 0015)

## 왜 했나

사용자가 카메라 잠금이 더 분명하게 느껴지기를 원했다. 풀리는 거리를 늘려 거의 맵 가장자리에서 풀리게 하기로 했다. 그런데 새를 화면 안에 두는 판정이 카메라 점 둘레의 고정 상자(x ±6, z ±5)라, 잠긴 동안 새는 그 상자 밖으로 못 갔다. 캠락 구간을 그보다 크게 하면 영원히 안 풀린다. 실제 화면은 쿼터뷰라 기울어진 사각형이고, 먼 쪽으로 20 m 넘게 보였다.

## 검증

Play Mode 에서 스크립트로 했다.

| 무엇 | 결과 |
|------|------|
| `script recompile`, 빌더 `Build` | 에러 0 |
| 잠근 뒤 오른쪽(+X, 카메라 쪽) 멀리 | x 13(범위 끝)까지 가서 풀림 |
| 잠근 뒤 왼쪽(−X) 멀리 | x −13.9 의 가지에 앉고 풀림 |
| 잠근 뒤 뒤쪽(z 0) | z 0 까지 가서 풀림 |
| 잠근 뒤 앞쪽(z 40) | z 25(빛나는 공간)에서 멈춤, 풀림 |
| 잠근 뒤 카메라 쪽 모서리(30, 0) | (11.4, 1.6) 까지, 풀림 |
| 빛나는 공간 너머(z 27) 클릭 | 가지에 앉아 `Refuse` |
| 콘솔 | 에러와 경고 0 |

처음에는 화면 좌표에서 잘랐다. 카메라 쪽 맵 모서리(13, 0)를 목표로 주자 새가 맵 반대편(z 36 쪽)으로 날아갔다. 그 점이 카메라의 가까운 쪽 평면 뒤에 있어 화면 좌표가 뒤집혔기 때문이다. 화면의 네 모서리를 땅 높이에 내려 월드에서 자르도록 바꿨다.

## 크로스 모델 리뷰

Codex. 정확성(화면 판정, 잠금이 풀릴 수 있는지, 거절), 보안, 견고성 렌즈. 범위는 `Assets/02_Scripts` 와 빌더의 diff.

| 지적 | 처리 |
|------|------|
| warn. 범위로 자르고 화면으로 자르고 다시 범위로 자르면, 맵 모서리에서 마지막 범위 자르기가 점을 기울어진 화면 밖으로 밀 수 있다 | 반영. 처음에는 번갈아 네 번 자르게 했다 |
| warn(확인 리뷰 1). 번갈아 잘라도 두 경계가 비스듬히 만나는 모서리에서는 교집합 안이 보장되지 않고, 매 프레임 같은 오차가 남는다 | 반영. 화면 사각형을 범위로 잘라(Sutherland-Hodgman) 겹치는 다각형을 만들고, 목표점이 그 밖이면 가장 가까운 변 위의 점으로 옮긴다. 번갈아 자르기는 없앴다 |

시험 중에 찾은 것: 처음의 화면 좌표 자르기가 카메라 쪽 모서리의 점을 뒤집어 반대편으로 보냈다(검증 절). 월드에서 자르도록 바꾼 뒤 두 번째 확인 리뷰를 돌렸다.

마지막 확인 리뷰는 `LGTM - no blockers` 였다.

## 남은 것

- 카메라가 0.4초 늦게 따라가므로, 새가 빨리 움직이면 화면 끝에 먼저 닿아 멈칫할 수 있다. 실제 마우스로 보고 `screenMargin` 을 맞춘다
- 잠금이 분명하게 느껴지는지 보고, 모자라면 구도 바꾸기나 비네트를 더한다
