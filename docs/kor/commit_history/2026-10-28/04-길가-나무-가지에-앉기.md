# 새가 길가 나무 가지에 앉고, 가만히 2초면 가까운 가지로 간다 (ADR 0009)

## 왜 했나

디렉터가 Q7(길가 나무는 장식만)을 뒤집었다. 모든 나무에 앉을 수 있는 가지와 앉는 지점이 있다. 플레이어가 아무것도 하지 않고 2초 동안 가만히 있으면 새가 가장 가까운 가지로 가서 앉는다. 클릭으로도 앉을 수 있다.

## 중요한 결정

- 고목 같은 장치에는 저절로 앉지 않는다. 새가 장치를 혼자 풀면 플레이어가 도울 몫이 없다
- 길 범위를 넓히지 않고, 앉기만 화면 안 어디서나 되게 했다. 새는 여전히 길 안에서 난다 (ADR 0007)
- `GameTuning.asset` 은 고치지 않았다. 새 값은 코드의 기본값(2)으로 읽힌다
- 안개 맵(`Sam_Fog_Test.unity`)은 다시 만들지도 시험하지도 않았다. 바뀐 코드는 안개 맵에도 쓰인다

## 검증

Play Mode 에서 스크립트로 했다. 실제 마우스로는 하지 않았다.

| 무엇 | 결과 |
|------|------|
| 시작 후 아무것도 하지 않기 | 새가 (1.5, 2.5, -1) 에서 가장 가까운 가지(3.2 거리)로 가 앉았다 |
| 앉은 채 화면 안의 다른 가지 클릭(`Click` 을 리플렉션으로, 실제와 같은 레이캐스트) | 그 가지(길 밖 x 7.68)로 가서 앉았다 |
| 길 밖 가지에서 땅 (0, 4) 클릭 | 길로 날아와 (0, 2.5, 4) 에 섰다. 2초 뒤 가장 가까운 가지로 가 앉았다 |
| 가지는 57 개 등록(나무 56 + 고목) | 고목에는 저절로 앉지 않았다 |
| 콘솔 | 에러와 경고 0 |

가상 마우스는 이번에 먹지 않았다. 클릭이 엉뚱한 곳으로 갔고, 다른 스크립트 호출에서 읽은 가상 마우스의 위치는 늘 (0, 0) 이었다. 그래서 클릭 처리는 `Click` 을 직접 불러 확인했다. 시험 동안 바꾼 Input System 설정과 가상 장치는 되돌렸다.

시험 시작 때 에디터가 Play Mode 였다(사용자가 돌린 것으로 보인다). 스크립트를 다시 컴파일하자 그 세션에서 `DevTools` 가 null 예외를 냈다. Play Mode 를 끄고 진행했다.

## 남은 것

- 실제 마우스로 클릭해 앉기를 확인한다

- 앉는 가지의 높이, 클릭 영역 크기, 2초는 디렉터의 피드백을 보고 맞춘다
