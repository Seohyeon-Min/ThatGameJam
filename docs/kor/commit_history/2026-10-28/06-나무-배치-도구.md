# 나무 배치를 다른 씬에서도 쓰는 `TreeGenerator` 컴포넌트로

## 왜 했나

디렉터 요청(Tree Generator). 나무 배치(`PlaceRoadsideTrees()`)가 `BuildSamTestScene` 안의 함수라 쓰려면 빌더 전체를 돌려야 했다. 그러면 `Sam_Test.unity` 와 나무 프리팹까지 다시 만들어져서 다른 씬에서는 쓰기 어려웠다. 디렉터는 자기 테스트 씬에서 나무 프리팹만 넣고 Generate 로 바로 배치해 보려고 한다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| 씬 오브젝트에 붙이는 `TreeGenerator`. 인스펙터에서 나무 프리팹 목록, 배치 구역 여러 개(그 오브젝트 기준 X, Z 의 두 모서리), 간격, 흔들림(간격에 대한 비율), 크기 범위, 무작위 회전, 시드를 정한다. 구역은 씬 뷰에 초록 테두리로 늘 보인다 | `Assets/02_Scripts/Tools/TreeGenerator.cs` |

## 중요한 결정

- "이 도구가 만든 나무" 는 컴포넌트가 직렬화한 목록으로 안다. 같은 오브젝트 아래에 다른 것을 두어도 Clear 가 지우지 않는다
- 나무 높이는 그 오브젝트의 높이(로컬 y = 0)다. 지금처럼 땅 높이를 재지 않는다
- 무작위 회전을 끄거나 크기 범위를 한 값으로 해도 난수는 그대로 뽑는다. 그래야 그 설정만 바꿨을 때 나무 자리와 종류가 바뀌지 않는다
- Undo: 목록을 먼저 바꾸고 나서 나무를 지운다. 나무를 만들 때는 다 만든 뒤 목록을 바꾼다. `Undo.DestroyObjectImmediate` 와 `RegisterCreatedObjectUndo` 가 그때까지 기록된 변경을 확정해, 순서가 반대면 되돌릴 때 목록이 비었다(첫 시험에서 그랬다)

## 검증

| 무엇 | 결과 |
|------|------|
| `script recompile` | 에러 0 |
| 바꾸기 전 씬과 바꾼 뒤 빌더로 다시 만든 씬의 나무 56 그루를 비교(프리팹, 위치, 회전, 크기를 `R` 형식 문자열로) | 모두 같다 |
| Clear → Ctrl+Z → Generate → Ctrl+Z (`Undo.PerformUndo`), 도구가 만들지 않은 자식 하나를 넣어 두고 | 자식 57 → 1 → 57 → 57 → 57. 목록의 나무 56 → 0 → 56 → 56 → 56, 모두 그 도구 아래. 다른 자식은 남았다 |
| 간격 0 으로 Generate | 경고를 내고 아무것도 하지 않았다. 간격 1, 3 × 3 구역은 9 그루 |
| 프리팹 칸에 씬 오브젝트를 넣고 Generate | 경고를 내고 있던 나무 9 그루를 그대로 두었다 |
| 콘솔 | 에러와 경고 0 |

인스펙터 버튼은 직접 누르지 않았다. 같은 함수를 스크립트로 불렀다.

## 크로스 모델 리뷰

Codex. 정확성(결과가 전과 같은지, Undo 순서), 보안, 견고성 렌즈. 범위는 빌더와 새 `.cs` 둘의 diff.

| 지적 | 처리 |
|------|------|
| warn. 새 컴포넌트에서 구역 배열이 null 이면 Generate 가 예외를 내고, 그 전에 Clear 로 나무를 지운다 | 반영. 두 배열을 빈 배열로 시작한다 |
| warn. 간격의 `Min` 은 인스펙터에서만 막는다. 스크립트로 0 이나 음수가 들어오면 반복이 끝나지 않아 에디터가 멈춘다 | 반영. Clear 전에 간격이 0.1 보다 작으면 경고하고 멈춘다 |
| warn(확인 리뷰 1). 프리팹 칸에 씬 오브젝트를 넣으면 나무를 지운 뒤 생성 중에 예외가 난다 | 반영. Clear 전에 모든 칸이 프리팹 에셋인지 본다. 씬 오브젝트를 넣고 Generate 하면 경고만 내고 있던 나무 9 그루가 그대로 남았다 |
| warn(확인 리뷰 1). 구역 좌표가 무한대거나 아주 크면 `x + spacing == x` 가 되어 반복이 끝나지 않는다 | 기각. 구역은 사람이 수십 m 크기 레벨에 손으로 적는 값이다. 그런 값을 막는 코드는 실제로 생기지 않는 경우를 위한 것이다 |

고친 뒤 두 번째 확인 리뷰는 `LGTM - no blockers` 였다.
