# 첫 통나무 끝에서 4.9 m 를 한 번에 뛰던 것을 착지점으로 고친다

## 왜 했나

사용자가 플레이타임을 계산하다 찾았다. `Main` 스테이지 1 의 아기 길에서 첫 통나무의 `BalanceBeamEnd`(`Point_74`, z 18.1, 높이 0.28)
바로 다음 점이 기울어진 고목의 `StopPoint`(`Point_75`, z 23.0)였다. `Baby.WakeAndWalk` 는 `BalanceBeamEnd` 다음 구간을
`Girl_Jump` 한 번(`JumpTo`, 1.5 초)으로 움직이므로, 아기가 4.9 m 를 한 번에 뛰었다. 같은 길의 다른 점프는 0.3 ~ 1.2 m 다.

`Sam_Test` 에서는 정지점이 통나무 끝 바로 뒤(z 18)에 있어 이 구간이 짧았다. `Main` 에서 고목 쪽이 뒤로 옮겨지면서 통나무 끝과 정지점
사이가 벌어졌다.

## 무엇을 바꿨나

| 무엇 | 자리 |
|------|------|
| `BalanceBeamEnd` 다음 점이 1.2 m 보다 멀면, 통나무 끝에서 다음 점 쪽으로 0.4 m(통나무가 아직 있으면 0.6, 0.8, 1.0 m) 앞 땅에 착지점 `<끝 점 이름>_Land` 를 넣는다. 높이는 `Ground` 레이어로 아래로 쏜 레이에서 통나무를 뺀 땅, 없으면 터레인이다. 점프는 이 짧은 구간만 하고, 나머지는 걷는다 | `AgentScripts/FixStage1LogLanding.cs` `Run` |
| 모든 길의 점프 구간 길이를 보여 주기만 하는 진입점 | 같은 파일 `Report` |

길의 다른 점, `BalanceBeamStart`/`End` 표시, `StopPoint` 는 그대로다. 런타임 코드는 바꾸지 않았다.

## 검증

이 기록을 쓴 세션에서는 Unity 를 실행할 수 없었다. 아래는 실행할 명령과 확인할 것이다.

| 무엇 | 확인할 것 |
|------|------|
| `unity command script run --file AgentScripts/FixStage1LogLanding.cs --entry FixStage1LogLanding.Report` (Main, Edit Mode) | Stage1 에 `Point_74->Point_75 4.91 m` 가 보인다 |
| 같은 파일 `--entry FixStage1LogLanding.Run` | `Point_74_Land` 가 생기고, 점프가 약 0.4 m, 그 뒤 걷기 약 4.5 m 로 나온다. Main 이 저장된다 |
| `Report` 다시 실행 | Stage1 의 점프가 모두 1.2 m 이하 |
| 씬 뷰 | `BabyRoute` 기즈모에서 통나무 끝의 청록 점프 호가 짧아졌고, 착지점이 물이 아닌 땅 위에 있다 |
| `VerifyStage1Logs.Play`, `Natural` | 통과. 아기가 통나무 끝에서 짧게 뛰어내린 뒤 걸어서 고목 앞에 멈춘다 |
| Play 중 콘솔 | 에러 0 |

## 남은 것

- 착지점이 땅 위에 있는지는 씬 뷰에서 눈으로 봐야 한다. 스크립트는 땅 높이만 재고, 물인지는 가리지 않는다.
- `BuildSamTestScene.SetupStage1Logs` 는 `Sam_Test` 배치(정지점이 통나무 끝 바로 뒤)에서는 이 문제가 없어 고치지 않았다.
