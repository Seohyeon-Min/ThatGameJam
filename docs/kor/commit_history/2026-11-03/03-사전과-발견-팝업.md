# 사전(Encyclopedia)과 발견 팝업, 이스터에그 목록 문서

## 왜 했나

디렉터의 지시(`order_from_director.md`)에 사전 시스템이 있다. 찾은 상호작용을 기록하고, 찾으면 스팀 도전과제처럼 팝업을 띄우고, 키를 누르면 사전이 아래에서 올라오고 뒤 배경이 흐려진다. 사용자가 `Sam_model_test`에서 만들라고 했다. 실제 상호작용 대신 토끼를 클릭하면 찾은 것처럼 한다. 같은 파일의 이스터에그 13개는 아직 만들지 않고 문서로만 정리하라고 했다.

사용자가 정한 것:

- 게임 안 글자는 영어만 쓴다. 기본 글꼴(`LegacyRuntime.ttf`)
- 찾은 기록은 한 판 동안만 기억한다. 저장하지 않는다
- 못 찾은 칸은 `???`
- 토끼를 누를 때마다 아직 못 찾은 다음 항목을 찾는다
- 블러는 URP 피사계 심도로 한다
- 사전을 여는 키는 ESC 대신 `` ` ``. 원본은 ESC 였으나 Main 의 인트로와 컷신이 개발 빌드에서 ESC 로 건너뛴다
- 사전을 보는 동안 게임이 멈춘다. 배경음은 들려도 되고 효과음은 나지 않는다
- 사전 칸은 디렉터 목록 13개 그대로 둔다

## 중요한 결정

- **효과음 멈추기.** FMOD 프로젝트에는 Master 버스 하나뿐이라 효과음만 골라 멈출 버스가 없다. 지금 효과음(발소리, 날갯짓)은 애니메이션 이벤트에서 나므로 `timeScale` 0 이면 같이 멈춘다. 그 밖의 효과음인 우클릭 울음은 `SoundManager` 에서 막았다. 바람과 음악은 계속 들린다. 나중에 시간과 상관없이 나는 효과음이 생기면 FMOD 에 SFX 버스를 두고 그 버스를 멈추는 편이 낫다.
- **항목을 에셋으로.** 실제 상호작용이 생기면 그 컴포넌트가 항목 에셋을 직접 참조하고 `Discover` 를 부른다. 번호나 이름 문자열로 찾지 않는다.
- **런타임 생성 없음.** 칸, 팝업, Volume 은 빌더가 프리팹에 저장한다. 런타임에는 글자, 색, 위치, weight 만 바꾼다.
- **글자 크기.** 처음 만든 칸(300 × 190)에서 긴 제목이 잘렸다. 칸을 310 × 230 으로 키우고 제목과 설명에 Best Fit 을 켰다.

## 크로스 모델 리뷰

GPT-6.1 Sol. 렌즈: 정확성, 보안, 견고성(`timeScale`, 정적 상태 포함). C# 변경을 세 번 리뷰했다.

| 등급 | 지적 | 처리 |
|------|------|------|
| warn | 목록에 없는 항목이나 null 을 `Discover` 에 넘기면 예외가 나고 찾은 목록이 오염된다 (세 번 모두) | **기각.** 항목은 에디터에서 정한 참조다. 잘못되면 예외가 바로 보이는 편이 낫다. 프로젝트는 지나친 방어 코드를 피한다 |
| warn | 다른 컴포넌트가 `Start` 전에 `Discover` 를 부르면 `Start` 가 칸을 못 찾은 상태로 덮는다 | **반영.** `Start` 와 `Discover` 가 같은 `ShowCard` 로 찾은 목록을 읽어 칸과 개수를 그린다 |

| warn | 칸 5 열이 좁은 화면에서 넘친다 | **반영.** CanvasScaler 를 Expand 로 바꿨다. 1920 × 1080 배치가 어떤 화면비에서도 화면 안에 들어간다 |

## 남은 것

- Main 에는 아직 붙이지 않았다. 붙일 때 `BirdController` 의 클릭과 울음도 `Encyclopedia.IsOpen` 으로 막아야 한다.
- 웹 빌드에서 `` ` `` 키가 브라우저에서 게임으로 들어가는지, Bokeh 블러의 비용이 괜찮은지 봐야 한다.
- 이스터에그 원본 안에서 서로 다른 곳(철새 횟수, 깃털의 스테이지 3, 눈 회오리 범위, `1, 3, 5, 8, 7,` 의 뜻)은 디렉터에게 물어야 한다 (`easter_eggs.md` 6절).
