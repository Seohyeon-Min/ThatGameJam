# 코드 구현 계획

> 근거: [`game_design.md`](game_design.md) (원본 `Game Design.pdf`). 아래 `§N` 은 그 문서의 절 번호다.
> 영어판: [`../eng/implementation_plan.md`](../eng/implementation_plan.md)
> 상태: 초안, 2026-10-27. 진행 상황은 6.1 에 있다. 5장의 질문 중 12개는 2026-10-27 에 정했다 ([ADR 0003](decisions/0003-구현-계획-질문의-답.md), [ADR 0004](decisions/0004-안개-자연-해결-규칙.md)). 남은 질문이 정해지면 고친다.

이 문서는 기획서를 코드 쪽에서 무엇으로 만들지 정리한다. 아트, 사운드, 레벨 배치는 코드가 붙을 자리(이벤트, 애니메이터 파라미터, 셰이더 값)까지만 다룬다.

## 1. 요약

게임 전체가 하나의 리듬을 반복한다. **잠든 아기 깨우기 → 아기가 길을 따라 걷기 → 장애물 앞에서 멈춤 → 새가 돕거나 시간이 지나 저절로 풀림 → 빛나는 공간에서 잠들기 → 계절 연출 → 다음 스테이지** (§11.3).

그래서 코드는 공통 틀을 먼저 만들고, 스테이지별 장치는 그 틀에 끼우는 작은 컴포넌트로 만든다.

| 공통 틀 | 하는 일 | 기획 근거 |
|---|---|---|
| 새 조작 | 좌클릭 이동과 내려앉기, 우클릭 울음, 맵별 고정 고도 | §2.1, §2.3 |
| 울음소리 | 범위 안의 "살아있는 것"에게 알린다 | §2.1, §9.3, §15.7 |
| 아기 | 길 따라 걷기, 멈춤, 반응(올려다보기), 잠, 깨어남 | §2.2, §2.4, §4 |
| 자연 해결 타이머 | 기다리는 시간, 3단계 신호, "새가 풀었나 / 저절로 풀렸나" | §3 |
| 빛나는 공간과 스테이지 전환 | 잠들기, 계절 연출, 화면 전환, 다음 스테이지 배치 | §10, §11 |
| 카메라 | 새를 따라가는 카메라. 새가 기믹 구간의 트리거를 넘으면 좁은 범위로 잠긴다. 새는 길 안에 있다 | §2.5, ADR 0005, ADR 0007, ADR 0008 |

| 스테이지별 장치 | 기획 근거 |
|---|---|
| 날개 우산 (튜토리얼) | §6.2 |
| 기울어진 고목 | §7.3 |
| 눈 쌓인 가지, 잠든 토끼 가족, 옆길 | §8.2, §8.3 |
| 안개 걷기, 빵가루 궤적, 숨은 장애물, 대답하는 동물 | §9.2 ~ §9.5 |
| 낭떠러지 너머 자동 상승, 구름 뚫기 | §9.6 |
| 엔딩 두 가지 | §12 |

## 2. 지금 코드와 기획의 차이

지금 `Sam_Test` 씬의 코드는 기획서 전의 시험용이다. 조작 방식이 기획과 다르다.

| 파일 | 지금 | 기획 | 할 일 |
|---|---|---|---|
| `BirdController.cs` | WASD 이동, 휠로 고도, E 로 장애물 치우기와 가지에 앉기 | 좌클릭 이동·상호작용, 우클릭 울음, 고도는 맵별 고정 (§2.3) | 입력 부분을 새로 쓴다. 날기 / 내려앉는 중 / 앉음 상태는 살린다 |
| `ChildWalker.cs` | 목표점까지 직선으로 걷고, `Obstacle` 이 앞에 있으면 멈춤 | 길(경로)을 따라 걷고, 장애물마다 다른 자세로 기다리고, 반응한다 (§2.2, §4) | 새로 쓴다. 이름도 기획서 용어에 맞춰 `Baby` 로 바꾼다 |
| `Obstacle.cs` | 새가 치우면 사라짐 | 모든 장애물은 시간이 지나면 저절로 풀리고, 3단계 신호를 낸다 (§3) | 4.4절의 자연 해결 타이머로 바꾼다 |
| `PerchPoint.cs` | 가까이 가면 표시가 깜빡이는 앉는 지점 | 상호작용 대상은 고목과 눈 쌓인 가지 (§2.1) | 내려앉는 위치로 계속 쓴다. 가까이 가면 깜빡이는 표시는 뺀다. 마우스를 올리면 커서만 바뀐다 (Q6) |
| `QuarterViewCamera.cs` | 대상을 계속 따라감 | 인트로만 따라가고, 스테이지에서는 구간별 고정 카메라 (§2.5) | 4.7절의 카메라 리그로 바꾼다 |
| `Tree.prefab` | 길가 나무. 가지에 앉을 수 있음 | 기획서에 길가 나무에 앉는 내용은 없다 | 장식으로만 남기고 앉는 지점은 뺀다 (Q7). 2026-10-28 에 4종 × 잎 없음/있음(`Trees/Tree_N_Bare`, `Tree_N_Leafy`)으로 바꿨다. 같은 날 디렉터가 Q7 을 뒤집어 모든 나무에 앉는 가지를 두었다 (ADR 0009). 2026-10-29 에 토미의 나무 3종(잎 없는 `tree01 ~ 03`, 잎 있는 `tree_l_01 ~ 03`)으로 바꿨다 (ADR 0019) |

`AGENTS.md` 의 "마우스 휠은 방향만 쓴다" 규칙은 기획에서 휠을 쓰지 않게 되면서 쓸 곳이 없어진다. `AGENTS.md` 는 고치지 않았다.

## 3. 구조

### 3.1 컴포넌트 목록

이름은 제안이다. 한 컴포넌트는 한 가지 일만 한다.

| 컴포넌트 | 하는 일 |
|---|---|
| `GameFlow` | 인트로 → 튜토리얼 → 스테이지 1·2·3 → 엔딩 순서를 진행한다. 지금 스테이지를 안다. 새가 날 수 있는 범위를 정한다 (ADR 0010) |
| `Stage` | 한 스테이지의 설정. 아기와 새의 시작 위치, 새 고도, 길 범위, 빛나는 공간 |
| `BirdCamera` | 카메라가 따라갈 점을 정한다. 새를 따라가되 `GameFlow` 가 연 길 범위를 넘지 않고, 잠긴 `CameraZone` 이 있으면 그 범위 안에 머문다. Cinemachine 카메라 하나가 이 점을 따라간다. 새가 화면 밖으로 못 나가게 하는 것은 `BirdController` 가 실제 화면으로 한다 (ADR 0005, ADR 0007, ADR 0015) |
| `CameraZone` | 장치 하나의 카메라 구간. 새가 트리거 띠에 들어오면 카메라가 사각형 범위로 잠기고, 새가 더 넓은 캠락 구간을 나가거나 장치가 풀리면 풀린다 (ADR 0007, ADR 0014) |
| `BirdController` | 클릭 이동, 내려앉기, 울음, 고도 |
| `Perchable` | 새가 내려앉을 수 있는 오브젝트. 앉으면 `Perched` 이벤트를 낸다. 지금의 `PerchPoint` 를 내려앉는 위치로 쓴다. 길가 나무의 가지는 "가만히 있으면 앉는 자리"다 (ADR 0009) |
| `CryListener` | 울음에 반응하는 것의 공통 부분. 반응 거리를 가진다. 아기, 안개 동물, 엔딩의 철새가 쓴다 |
| `Baby` | 아기의 상태(4.3절)와 이동 |
| `BabyRoute` | 아기가 걷는 길. 점의 목록이다 |
| `StopPoint` | 길 위에서 아기가 멈추는 자리. 어느 장애물을 기다리는지, 어떤 자세로 기다리는지 가진다 |
| `NaturalTimer` | 자연 해결까지의 시간, 3단계 신호, 해결. §3.2 표의 다섯 지점이 모두 이것을 쓴다 |
| 빛나는 공간 | 아기 길(`BabyRoute`)의 마지막 점과 그 위의 빛. 아기가 마지막 점에 오면 잠들고 `ReachedRest` 를 낸다. 컴포넌트나 구간을 따로 두지 않는다 (ADR 0006) |
| `GameTuning` | 시간과 속도 값을 모은 ScriptableObject (`Assets/04_Data/`) |
| `Season` | 계절 단계 0 ~ 4. `AdvanceSeason()`, `OnSeasonChanged(int)` (4.15절, ADR 0018) |
| `SeasonDebugTint` | 디버그용. 계절 단계만큼 환경을 빨갛게 칠한다. 연출 에셋이 오면 지운다 |
| `SeasonSnow` | 눈. 계절 0(인트로)에서만 내리고, 1 이 되면 새 눈만 멈춘다 (4.9절, ADR 0018) |
| 스테이지 장치 | `WingUmbrella`, `LeaningLog`, `SnowBranch`, `RabbitFamily`, `FogField`, `FogTrail`, `FogAnimal`, `HiddenObstacle`, `CloudCover`, `Ending`, 계절 연출들 |
| `DevTools` | 개발용. 시간 빨리 감기, 스테이지 건너뛰기. 화면 위쪽의 버튼 줄. 릴리스 빌드에서는 끈다 |
| `TreeGenerator` | 레벨 도구. 구역 안에 나무 프리팹을 흩어 놓는다. 터레인을 주면 그 표면에 세운다. 인스펙터의 Generate, Clear 버튼 |

### 3.2 흐름

```text
GameFlow ──시작──▶ Stage ──▶ Baby (잠든 채 배치)
                               │ 울음 또는 NaturalTimer 끝 → 깨어남
                               ▼
                         BabyRoute 따라 걷기
                               │ StopPoint 도착
                               ▼
                 장치(LeaningLog 등).NaturalTimer 시작
                               │ 새가 풀거나(byBird) 시간이 다 됨(byNature)
                               ▼
               Baby 반응(byBird 면 올려다봄) → 이어지는 길로 걷기
                               │ 길의 끝(빛나는 공간) 도착
                               ▼
               잠들기 → 계절 연출 → GameFlow 가 다음 Stage 로 전환
```

장치와 아기 사이에는 `Resolved(bool byBird)` 이벤트 하나만 둔다. 아기는 장치의 종류를 모른다. `StopPoint` 가 기다리는 자세와 해결 뒤 이어질 길을 알려 준다.

### 3.3 씬 구성

하나의 게임 씬에 모든 스테이지를 +Z 로 한 줄의 긴 길로 잇는다. 스테이지마다 루트 오브젝트가 하나다. 다음 스테이지는 아기가 잠든 빛나는 공간에서 시작한다. 순간이동도 화면 덮기도 없다 (ADR 0010). 첫 스테이지는 인트로다 (ADR 0018). 땅은 모든 스테이지 아래의 커다란 터레인 하나이고, 카메라가 어디를 보아도 끝이 보이지 않게 나무로 덮는다 (ADR 0019). 웹에서 한 번만 불러오면 되고, 스테이지 사이에 넘길 상태(엔딩 분기 등)를 따로 저장할 필요가 없다.

각 스테이지는 프리팹으로 만든다. 그러면 여러 사람이 각자 테스트 씬에서 다른 스테이지를 만들고, 공용 씬에서는 프리팹만 놓으면 된다. 씬 파일 충돌이 줄어든다. 공용 게임 씬은 `Main.unity` 다 (Q1).

## 4. 시스템별 구현

### 4.1 입력과 새 이동 (§2.1, §2.3)

- 입력은 Input System 의 `<Mouse>/leftButton`, `<Mouse>/rightButton`, `<Mouse>/position` 만 쓴다.
- 좌클릭하면 카메라에서 마우스 위치로 레이를 쏜다. 맞는 레이어는 셋이다.
  - `Interactable`: `Perchable` 에 맞으면 새가 그 내려앉는 위치로 날아가 앉는다.
  - `Ground`: 맞은 점의 XZ 로 날아간다. 높이는 스테이지의 고정 고도다.
  - `ClickPlane`: 낭떠러지 너머처럼 땅이 없는 곳에 둔 보이지 않는 큰 평면이다 (§2.3). 물의 콜라이더도 이 레이어라, 물을 누르면 그 수면으로 간다. 아기의 이동 판정은 이 레이어를 무시한다.
  - 처음 맞은 것이 지금 앉을 수 없는 `Interactable`(화면 밖 가지의 앉기 영역, 쓰러진 고목)이면, `Ground` 와 `ClickPlane` 만 다시 쏴서 그 뒤의 자리로 간다.
- 앉아 있을 때 땅을 클릭하면 날아오른다.
- 새는 물리로 밀고 당기지 않는다. 지형과 장애물 위를 넘어 다니므로 (§2.1) 목표점으로 직접 옮긴다. 지금의 Rigidbody 속도 방식은 버린다.
- 새는 스테이지의 범위(길과 그 옆 땅) 밖으로, 화면 밖으로 (Q3) 나갈 수 없다 (ADR 0007, ADR 0013). 화면은 메인 카메라가 비행 높이에서 실제로 보여 주는 기울어진 사각형이다. 가장자리에서 화면의 8%(`screenMargin`) 안쪽까지다. 앉을 수 있는 가지도 실제 화면 안이다 (ADR 0015). 클릭한 목표점은 자르지 않는다. 그래서 새는 범위 끝에 붙어 있다가, 카메라가 따라가면 계속 간다. 3-3 은 낭떠러지 너머 위쪽까지 범위에 넣는다.
- 좌클릭을 누르고 있는 동안에는 목표점을 계속 갱신한다 (Q12). 안개에 길을 그릴 때 편하다.
- 클릭한 자리에 작은 원을 잠깐 보인다 (Q13).
- 내려앉을 수 있는 대상에 마우스를 올리면 커서만 바뀐다. 다른 표시는 하지 않는다 (Q6). 조작 안내를 줄이는 목표(§1.3)와 신호가 곧 힌트라는 규칙(§3.1)을 따른다.
- 새 모델과 애니메이션은 아트의 `Bird-Animated` 다. `BirdController` 는 Animator 에 `Moving`, `Perched`(내려앉는 중 또는 앉음), `Refuse`(고개 젓기) 세 값만 넘긴다. 이동 중에는 활공하고 2초마다 날갯짓을 한 번 한다. 제자리에 떠 있으면 `Bird_Hover`(시험 중, ADR 0011), 날아오른 직후에는 날갯짓 한 번, 앉을 자리에 도착하면 내려앉기, 앉아 있으면 대기 3종을 무작위로, 떠날 때 날아오르기. 흐름은 빌더가 만드는 `Bird.controller` 에 있다.
- 새의 위치는 발끝이다. 앉는 자리(`Perchable` 의 점)에 발이 놓인다.
- 모든 길가 나무에 앉는 가지가 하나 있다. 클릭하면 앉는다. 날고 있는 새가 입력 없이 2초(`birdIdlePerchDelay`) 가만히 있으면 화면 안에서 가장 가까운 가지로 가서 앉는다. 장치(고목 등)에는 저절로 앉지 않는다. 새는 길과 그 옆 땅(x ±25, 길 폭의 5배) 위를 날고, 앉기는 화면 안 어디서나 된다 (ADR 0009, ADR 0013, ADR 0019). 단 날 수 있는 범위의 앞뒤 끝을 넘어 앉지는 않는다 (ADR 0010).
- 지금 스테이지의 빛나는 공간 너머를 누르거나 끌면, 새는 그 선까지 날아간다. 목표가 선 너머인 채로 선에 닿으면 화면 안의 가장 가까운 가지에 앉아 고개를 젓는다(`Bird_Refuse`). 화면 안에 가지가 없으면 그 자리에 머문다 (ADR 0011, ADR 0012, ADR 0016).
- 새는 `Bird` 레이어에 있다. 나무나 잎에 가려지면 가려진 부분이 하늘색 단색 실루엣으로 보인다. 두 URP 렌더러의 Render Objects 기능 둘(`BirdVisible`, `BirdSilhouette`)이 스텐실로 한다. 셋업은 `AgentScripts/SetupBirdSilhouette.cs` 다.

### 4.2 울음소리 (§2.1, §9.3, §15.7)

- 우클릭하면 `BirdController.Cry()` 가 울음 애니메이션과 소리를 낸다. 연타를 막는 짧은 쿨다운을 둔다.
- 등록된 모든 `CryListener` 에게 새의 위치를 알린다. 각 리스너가 자기 반응 거리로 반응할지 정한다.
  - `Baby`: 잠들어 있고 거리 안이면 깨어나 새를 올려다본다. 거리와 판정은 기획 미정 (§16).
  - `FogAnimal`: 소리를 내고 실루엣이나 작은 빛을 잠깐 보인다 (4.12절).
  - 엔딩의 철새: 해피 엔딩에서만 대답한다 (4.14절).
- 리스너 목록은 지금 `PerchPoint.All` 처럼 정적 목록으로 둔다. 별도의 이벤트 시스템은 만들지 않는다.

| 상태 | 들어가는 때 | 나가는 때 |
|---|---|---|
| `Sleeping` | 스테이지 시작, 빛나는 공간 도착 | 울음, 또는 깨어남 타이머 끝 |
| `Waking` | 깨어남 | 반응(올려다봄 또는 둘러봄) 애니메이션 끝 |
| `Walking` | 걷기 시작, 장애물 해결 | `StopPoint` 또는 길의 끝 도착 |
| `Waiting` | `StopPoint` 도착. 자세는 `StopPoint` 가 정한다: 서기, 쪼그려 앉기(토끼), 앉기(쉼돌) | 장치의 `Resolved` |
| `Reacting` | `Resolved(byBird: true)`. 새를 올려다본다. 토끼는 들여다본 뒤 올려다본다 | 반응 애니메이션 끝 |

**이동**

- `BabyRoute` 는 점의 목록이다. 점마다 높이를 가진다. 쓰러진 고목 위처럼 높이가 바뀌는 길을 점으로 그린다.
- 아기는 다음 점으로 일정 속도로 걷는다. 길 찾기(NavMesh)는 쓰지 않는다. 길이 한 줄이고 갈림은 장치가 정하기 때문이다.
- 갈림길은 토끼 장면 하나다. 옆길이 열리면 `StopPoint` 가 옆길 점 목록으로 바꿔 준다 (4.11절).
- 안개 구간에서만 길 대신 새의 궤적을 따라간다 (4.12절).
- 낭떠러지(§2.4)는 길의 끝이다. 3-3 의 길은 쉼돌에서 끝나고 아기는 앉는다.

**반응** (§4.1)

- 올려다보기 하나로 통일한다. 새 쪽으로 몸과 고개를 돌리고 잠깐 멈춘다.
- 해결 이벤트가 `byBird` 를 알려 준다. `true` 면 반응한 뒤 걷고, `false` 면 반응 없이 걷는다.
- 도움 횟수에 따라 반응을 키울지는 기획 미정이다 (§16). 아기가 도움 횟수를 세어 두기만 하면 나중에 붙일 수 있다.

**애니메이션 목록** (아트에 넘길 것): 걷기, 서서 기다리기, 쪼그려 앉기, 앉아 쉬기, 잠, 뒤척임, 눈 비비기, 기지개, 올려다보기, 둘러보기, 들여다보기, 바라보기(토끼가 지나갈 때).

아트의 소녀 모델(`Assets/01_Arts/Models/Girl/NPC-Girl-Animated.fbx`, 2026-10-28)의 클립을 상황에 이렇게 쓴다. Animator 는 빌더가 만드는 `Girl.controller` 이고, `Baby` 는 `Walking`, `Asleep`, `LookAround` 세 값만 넘긴다.

| 상황 | 클립 |
|---|---|
| 스테이지 시작, 잠듦 | `Girl_Sleep` 반복 |
| 깨어남 | `Girl_GetUp`(12.6 초)이 끝나야 걷는다. 그 뒤 새가 깨웠으면 숨쉬기를 하며 새 쪽으로 돈다. 혼자 깼으면 `Girl_Idle_LookAround` |
| 걷기 | `Girl_Walk` |
| 장치 앞에서 기다리기, 새가 도와 올려다보기, 안개에서 궤적 기다리기 | 서서 쉬기. 숨쉬기(`Girl_Idle_Breathing`), 흥얼거리기(`Girl_Idle_Hum`), 기지개(`Girl_Idle_Stretch`) 중 하나가 끝날 때마다 다음 것을 무작위로 |
| 빛나는 공간 도착 | `Girl_LieDown` → `Girl_Sleep`. 눕기가 끝나야 계절 연출과 전환이 시작된다 |

아직 클립이 없는 것: 쪼그려 앉기, 앉아 쉬기, 대기 신호(뒤척임, 눈 비비기, 기지개), 올려다보기, 들여다보기, 바라보기. 쪼그려 앉기와 앉아 쉬기 자리에서는 서서 기다린다. `Girl_Run` 은 쓰지 않는다.

### 4.4 자연 해결 타이머와 대기 신호 (§3)

§3.2 표의 다섯 지점(깨우기, 고목, 토끼, 안개, 구름)은 모두 같은 모양이다. 시간이 흐르고, 신호가 3단계로 커지고, 시간이 다 되거나 새가 먼저 풀면 끝난다. 그래서 `NaturalTimer` 컴포넌트 하나로 만든다.

- 값: 자연 해결까지 걸리는 시간 (`GameTuning` 에서 읽는다), 신호 1·2·3 단계가 시작되는 시점 (전체 시간에 대한 비율).
- 이벤트: `Signal1`, `Signal2`, `Signal3`, `Resolved(bool byBird)`. 신호 이벤트에 애니메이터 트리거, 파티클, 소리를 인스펙터에서 연결한다. 모든 신호에 시각 효과와 소리를 함께 붙인다 (§3.1).
- `Begin()`: 아기가 그 장치 앞에 멈췄을 때 부른다. 아기가 오기 전에는 시간이 흐르지 않는다 (Q4).
- `ResolveByBird()`: 새가 풀었을 때 장치가 부른다. 남은 시간을 건너뛰고 `Resolved(true)` 를 낸다.
- 신호가 나오는 오브젝트가 곧 상호작용 대상이다 (§3.1). 신호를 낼 오브젝트는 레벨 디자인에서 정한다.

### 4.5 깨우기 (§2.2, §5.2, §11)

- 아기에게 `NaturalTimer` 를 하나 둔다. 약 10초, 신호는 뒤척임 → 눈 비비기 → 기지개.
- 울음으로 깨면 올려다보기, 혼자 깨면 둘러보기를 한 뒤 걷는다 (§4.2).
- 인트로에서는 깨어난 뒤 컷신을 재생한다 (§5.2 Phase 3). 컷신은 Timeline(이미 설치됨)으로 만든다. 내용은 기획 미정.
- 스테이지 1·2·3 시작도 같은 방식이다 (§11.2). 스테이지 3 끝에서는 깨우지 않고 엔딩으로 간다.

### 4.6 빛나는 공간, 스테이지 전환, 게임 흐름 (§10, §11)

- 빛나는 공간은 특별한 구간이 아니다 (ADR 0006). 스테이지의 마지막 장치 바로 뒤, 아기 길의 끝에 포탈 같은 빛 하나를 둔다. 그 뒤로 길이나 땅을 더 이어 만들지 않는다.
- 아기가 길의 끝에 도착하면: 아기가 눕고 잠든다 → 계절이 한 단계 오른다(4.15절) → `GameFlow` 가 그 자리에서 다음 스테이지를 시작한다 (ADR 0010).
- 다음 스테이지: 아기는 잠든 채 그 자리에 있고(`Sleeping`), 깨우기 타이머가 다시 돈다. 새 고도는 새 스테이지의 값으로 천천히 바뀐다. 새가 날 수 있는 길에 새 스테이지가 더해진다.
- 새가 날 수 있는 범위: 지금 스테이지까지 모든 스테이지의 길과 그 옆 땅(`Stage.area`, ADR 0013, ADR 0019). 지금 스테이지에서는 그 스테이지의 빛나는 공간(아기 길의 마지막 점)의 Z 까지만 앞으로 간다. 장치는 새를 막지 않는다. 뒤로는 늘 간다 (ADR 0010, ADR 0012).
- 개발용 "다음 스테이지" 만 순간이동한다. 아기를 지금 스테이지의 빛나는 공간에 잠든 채로 두고 다음 스테이지를 시작한다. 새도 다음 스테이지 시작 위치로 옮긴다.
- 빛나는 공간의 빛(구름 틈과 햇빛)은 아트 작업이다 (§16). 코드는 켜고 끄는 것만 한다.
- 마지막 스테이지의 빛나는 공간은 처음에 꺼져 있고, 구름이 뚫리거나 갈라지면 켜진다 (§10.3, 4.13절).

### 4.7 카메라 (§2.5)

- 카메라는 새를 따라간다 (ADR 0005). 기획서 §2.5 의 "구간마다 고정 카메라" 를 사용자가 바꿨다. 기믹 구간에서는 고정 대신 좁은 범위로 잠긴다 (ADR 0007).
- Cinemachine 을 쓴다 (Q2). 메인 카메라에 `CinemachineBrain`, 쿼터뷰 각도로 고정한 `CinemachineCamera` 하나가 `CinemachineFollow` 로 한 점을 따라간다.
- 그 점은 `BirdCamera` 가 매 프레임 정한다. 새의 위치를 길 범위 안으로 자른다. 아기는 기준으로 쓰지 않는다. 새와 아기는 따로 움직이는 존재라는 것을 보이기 위해서다 (ADR 0007).
- 장치마다 `CameraZone` 을 둔다. 새가 트리거 띠(길을 가로지르는 사각형)에 들어오면 그 점이 1초 동안 부드럽게 구간의 사각형 범위 안으로 들어가고, 그 안에서 새를 따라간다. 범위는 작게 잡아 잠긴 동안 카메라가 거의 움직이지 않는다. 새가 트리거를 둘러싼 더 넓은 캠락 구간을 나가면 1초 동안 부드럽게 풀리고, 다시 트리거에 들어오면 또 잠긴다. 장치가 풀리면 풀리고 다시 잠기지 않는다. 새는 화면 밖으로 못 나가므로 캠락 구간은 잠긴 화면 안에 들어오게 잡는다. 고목은 맵 가장자리 가까이(x ±10, z 10 ~ 24)에서 풀린다 (ADR 0014, ADR 0015).
- 스테이지가 바뀌어도 카메라는 끊지 않고 계속 새를 따라간다. 개발용 "다음 스테이지" 로 새를 옮길 때만 끊는다 (ADR 0010).
- 인트로에서는 새를 따라가는 줌아웃 카메라를 쓰다가, 새가 아기에게 일정 거리 안으로 들어오면 스테이지 카메라로 바꾼다 (§5.2 Phase 2).
- 3-3 상승 구간의 카메라는 기획 미정이다 (§16). 우선 새의 높이를 따라 위로 올리는 카메라로 시험해 본다.

### 4.8 인트로 (§5)

지금은 장치 없는 스테이지 하나다 (ADR 0018, 디렉터의 그림). 아기가 길 시작에 잠들어 있고 눈이 온다. 깨어나 약 21 m 를 걸어 빛나는 공간에서 잠들고, 그곳에서 스테이지 1 이 시작된다. 기획서의 튜토리얼 눈 구간(§6)도 이 스테이지가 맡는다. 아래의 줌아웃 카메라, 높은 고도, 컷신은 아직 없다.

- 시작 상태: 눈이 내린다. 아기는 잠들어 있다. 카메라는 줌아웃. 새는 카메라 가까운 높은 곳에 있다.
- 조작 안내 UI 는 없다 (§5.2 Phase 1).
- 새가 아기에게 가까워져 인트로 카메라가 스테이지 카메라로 바뀔 때, 새도 같이 인트로의 높은 고도에서 스테이지 고도로 내려온다 (Q8).
- 깨어남 → 컷신 → 아기가 걷기 시작 → 튜토리얼 구간에 들어가면 전환 (§5.2 Phase 4).

### 4.9 튜토리얼 눈 구간과 날개 우산 (§6)

- `WingUmbrella`: 새가 아기 위에 있는지 매 프레임 본다. 수평 거리가 반지름 안이고 새가 아기보다 높으면 "덮고 있음" 이다.
- 덮고 있을 때 아기 위에 새의 그림자를 보인다. 실제 그림자는 빛 방향 때문에 아기 위에 떨어지지 않을 수 있다. 그래서 새 바로 아래에 가짜 그림자(URP Decal Projector 나 반투명 원판)를 둔다.
- 덮기 시작하면 아기가 올려다본다. 너무 자주 하지 않도록 쿨다운을 둔다.
- 우산은 이동과 진행에 아무 영향이 없다 (§6.2). 아기는 걸으면서 올려다보는지, 잠깐 멈추는지는 애니메이션을 보고 정한다.
- 날개 우산은 아직 없다.
- 눈: 서현 님의 `Snowfall` 파티클 하나. 카메라가 보는 땅을 덮는 상자에서 내리고, 카메라가 따라가는 점을 따라다닌다. 계절 0(인트로)에서만 내리고, 1 이 되면 새로 내리는 것만 멈춘다(`SeasonSnow`, ADR 0018). 땅과 부딪히는 계산을 하지 않고 땅에 가려지게 둔다. 새 아래로 눈이 떨어지지 않게 하는 것(파티클 Collision 으로 새에 닿은 눈 지우기)은 아직 없다. 웹 성능을 보고 정한다.

### 4.10 스테이지 1 — 고목 (§7)

- 1-1 쓰러진 고목: 장치가 아니다. 길 점을 고목 위로 그리기만 하면 된다.
- 1-2 `LeaningLog`:
  - 꼭대기에 `Perchable` 이 있다. 새가 앉으면 `ResolveByBird()`.
  - `NaturalTimer` 약 30초. 신호는 삐걱 소리 → 흔들림 커짐 → 밑동 갈라짐. 흔들림은 바람 세기와 같이 커지게 코드로 흔든다.
  - 해결되면 밑동을 축으로 물 쪽으로 쓰러지는 애니메이션을 재생한다. 쓰러지는 방향은 고정이다 (§7.3).
  - 쓰러진 뒤 아기의 길이 고목 위로 이어진다.
  - 고목이 쓰러지기 시작하면 앉아 있던 새는 저절로 날아올라 그 자리 바로 위에 뜬다 (Q5).
  - 아기가 도착하기 전에 새가 먼저 앉아 쓰러뜨려도 된다. 그때 아기는 멈추지 않고, 고목 앞에서 올려다본 뒤 건넌다 (Q4, §4.2).
- 1-3: 빛나는 공간. 계절 연출은 어미와 새끼 토끼들이 정해진 길로 줄지어 지나가는 것 (§7.4). `BabyRoute` 와 같은 점 목록을 쓰는 단순한 이동이다.

### 4.11 스테이지 2 — 잠든 토끼 가족 (§8)

- 2-1 시연: 아기가 트리거를 지나면, 작은 새 한 마리가 정해진 길로 날아와 가지에 앉았다 떠난다. 그때 `SnowBranch` 의 해결 애니메이션을 같이 재생한다. 위치와 타이밍은 기획 미정 (§16).
- `SnowBranch`: 눈 쌓인 휘어진 가지. 새가 앉으면 눈이 떨어지고 가지가 튀어 오른다. 2-1 과 2-2 가 같은 컴포넌트를 쓴다.
- `RabbitFamily` (2-2):
  - 아기는 그 앞의 `StopPoint` 에서 쪼그려 앉는다. 물리적으로 막힌 것이 아니다 (§8.3). 그래서 토끼에 콜라이더 판정을 하지 않고 `StopPoint` 로만 멈춘다.
  - `NaturalTimer` 약 30초. 신호는 가지에서 눈가루 → 새끼 뒤척임 → 어미 하품과 기지개.
  - 옆길을 막은 가지가 모두 풀리면 `ResolveByBird()`. 아기는 가족을 들여다보고, 새를 올려다보고, 옆길 점 목록으로 간다.
  - 시간이 다 되면 토끼들이 깨어나 길을 비켜 지나간다. 아기는 그것을 바라본 뒤 원래 길로 간다.
  - 가지 수는 기획 미정이다 (§16). 코드는 가지 N 개를 받고, 모두 풀려야 옆길이 열린다 (Q9).
- 새는 토끼를 건드리지 않는다 (§8.3). 토끼는 `Perchable` 이 아니므로 클릭해도 그 자리 땅으로 날아갈 뿐이다.

### 4.12 스테이지 3 — 안개 (§9.2 ~ §9.5)

가장 어렵고 위험한 부분이다. 다른 작업과 따로 먼저 시험 버전을 만드는 것을 제안한다 (6장).

**안개 데이터와 그리기 (`FogField`)**

- 안개 구간 위를 덮는 낮은 해상도의 격자(예: 128×128)를 하나 둔다. 칸마다 안개 진하기 0~1.
- 이 격자가 안개의 유일한 원본이다. 화면 표시와 아기의 판정이 모두 여기서 읽는다.
  - 표시: 격자를 매 프레임 `Texture2D` 로 올리고, 안개 메시(지면 위의 평면 몇 장)의 셰이더가 월드 XZ 로 이 텍스처를 읽어 투명도를 정한다.
  - 판정: "이 점이 걷혔나" 를 격자 값으로 본다.
- 새가 지나가는 곳은 부드러운 원 모양으로 값을 줄인다. 걷히는 폭은 기획 미정 (§16).
- 3-1 은 처음부터 길의 절반만 안개, 3-2 는 전부 안개로 시작한다. 처음 상태는 마스크 텍스처 하나로 칠해 둔다.
- 안개가 다시 차오르지는 않는다. 기획에 그런 내용이 없다.

**새의 궤적 (`FogTrail`)**

- 새가 안개 구간 위에서 일정 거리(예: 0.5m)를 움직일 때마다 점 하나를 더한다. 점의 높이는 아래로 레이를 쏴 땅 높이로 한다.
- 궤적은 아기에게서 시작해야 한다. 아기가 따라갈 궤적이 남아 있지 않을 때 새가 아기 근처 일정 거리 안을 지나면, 그때부터 새 궤적을 시작한다. 이 "근처" 거리가 기획의 "궤적을 다시 이어가는 판정 범위" 다 (§16). 아기가 아직 걷는 중이면 새가 가까이 와도 궤적을 끊지 않는다. 새가 아기 바로 앞에 떠 있기만 해도 출구 쪽이면 아기를 그 아래까지 이끈다.
- 루프 제거 (§9.2): 새 선분이 앞의 선분과 교차하면 교차점 사이의 점들을 지운다. XZ 평면의 2D 선분 교차 검사다.

**아기의 궤적 따라가기**

- 아기는 궤적 점을 순서대로 걷는다. 갈림길 판정은 하지 않는다 (§9.2).
- 다음 점으로 가기 전에 그 점을 검사한다. 걸을 수 있는 땅(`Ground` 레이어, 물이나 낭떠러지가 아님) 위가 아니거나, 가는 길에 `HiddenObstacle` 이 있으면 멈춘다. 그 뒤의 궤적은 지운다 (§9.2). 실패 화면은 없다.
- 궤적이 없으면 아기는 그 자리에서 기다린다.

**숨은 장애물과 동물**

- `HiddenObstacle`: 바위, 물웅덩이 등. 콜라이더만 있으면 된다. 안개 메시 아래에 있어 보이지 않는다.
- `FogAnimal` (`CryListener`): 울음에 반응해 소리와 짧은 빛이나 실루엣을 보인다. 아기가 가까이 오면 옆으로 비킨다. 걸을 수 있는 땅에만 둔다 (§9.3). 배치 규칙이라 코드가 아니라 레벨 디자인이 지킨다.

**자연 해결** (§9.2, §3.2)

- 구간마다 정답 길(점 목록)을 레벨 디자인이 그려 둔다.
- `NaturalTimer` 구간당 약 30초. 신호는 안개 가장자리가 옅어짐 → 숨은 동물 소리 → 경로 윤곽이 비침.
- 시간이 다 되면 정답 길을 따라 안개가 서서히 걷히고, 아기는 정답 길을 따라 걷는다.
- 시간은 아기가 처음 안개 앞에서 멈출 때부터 계속 흐른다. 새가 궤적을 그리는 동안에도 멈추지 않는다 (Q10).
- 자연 해결이 오면 아기는 남은 궤적을 버리고 가까운 정답 길 점으로 가서 정답 길을 따라 걷는다 (Q10). 정답 길에서 떨어져 있으면 물을 가로지르지 않도록 걸어온 궤적을 되짚어 정답 길 근처까지 돌아간 뒤 합류한다. 정답 길에서는 뒤로 가지 않고 가장 가까운 구간의 끝 점으로 간다.

### 4.13 3-3 — 낭떠러지와 구름 뚫기 (§9.6)

- 아기는 쉼돌 `StopPoint` 에서 앉는다. 이 `StopPoint` 는 길의 끝이다.
- 새의 고도: 낭떠러지 선을 넘은 거리에 따라 고도를 올린다. 입력은 그대로 좌클릭 이동이다 (§9.6). `ClickPlane` 덕분에 허공도 클릭할 수 있다.
- 고도가 구름 높이에 닿으면 `CloudCover.ResolveByBird()` → 구름에 구멍, 햇빛이 한꺼번에 쏟아짐 → 해피 엔딩.
- `CloudCover` 의 `NaturalTimer` 약 40초. 신호는 구름 사이 희미한 빛 → 바람 → 빛줄기. 시간이 다 되면 구름이 천천히 갈라짐 → 노말 엔딩.
- 새를 아기 곁에서 떠나게 하는 끌림은 기획 미정이다 (§16). 코드는 신호 이벤트로 켤 수 있게만 둔다.

### 4.14 엔딩 (§12)

- `Ending` 은 `CloudCover` 가 낸 `byBird` 로 분기한다.

| 항목 | 노말 (`byBird = false`) | 해피 (`byBird = true`) |
|---|---|---|
| 햇빛 | 천천히 켜짐 | 한꺼번에 켜짐 |
| 아기 | 바로 잠듦 | 새를 올려다본 뒤 잠듦 |
| 봄의 확산 | 아기 중심으로 퍼짐 | 같음 + 철새 떼가 날아옴 |
| 마지막 울음 | 대답 없음 | 철새들이 대답 (`CryListener`) |

- 마지막 울음을 언제, 누가 내는지는 기획에 없다 (Q11).
- 철새 떼: 정해진 길을 따라 나는 새 몇 마리. 무리 시뮬레이션은 하지 않는다.
- 최종 화면은 기획 미정 (§16).

### 4.15 계절 변화 연출 (§10.2, §15.9)

계절은 `Season` 컴포넌트의 단계다. 다섯 단계이고 스테이지와 맞는다 (ADR 0018).

| 단계 | 구간 | 모습 |
|---|---|---|
| 0 | 인트로 | 아기가 깨어나서 걷는다. 눈이 펑펑 온다 |
| 1 | 스테이지 1, 고목 | 눈이 그치고 잔잔해진다 |
| 2 | 스테이지 2, 토끼 | 소동물이 나오기 시작한다. 꽃이 보인다 |
| 3 | 스테이지 3, 안개 | 동물들이 많이 보인다. 나무에 잎이 달린다 |
| 4 | 엔딩 스테이지 | 꽃밭이 피어난다 |

지금 실제로 바뀌는 것은 눈뿐이다(`SeasonSnow`). 나머지는 디버그용 빨간 칠로만 구분한다. 아기가 빛나는 공간에서 잠들어 다음 스테이지가 시작될 때마다 `AdvanceSeason()` 으로 하나 오르고, `OnSeasonChanged(int 단계)` 이벤트가 난다. 아래 연출은 이 이벤트에 붙인다. Play Mode 의 인스펙터에서 "Advance Season" 과 "Apply Level"(적어 둔 단계로) 버튼으로 시험한다. 연출 에셋이 오기 전까지는 디버그용 `SeasonDebugTint` 가 아기와 새를 뺀 모든 것을 단계만큼 빨갛게 칠한다. 머티리얼은 바꾸지 않는다. 씬의 `SeasonDebugTint` 오브젝트를 지우면 없어진다.

| 시점 | 연출 | 코드 쪽 방법 |
|---|---|---|
| 인트로 끝 (단계 1) | 내리던 눈이 멈춤 | 눈 파티클의 새 방출을 멈춘다 (`SeasonSnow`, 했다) |
| 스테이지 1 끝 | 토끼 가족이 지나감 | 4.10절. 점 목록을 따라 이동 |
| 스테이지 2 끝 | 쌓인 눈이 녹음 | 전역 셰이더 값 `_SnowAmount` 를 줄인다. 땅과 소품 머티리얼이 이 값을 읽는다 |
| 마지막 | 아기 중심으로 봄이 퍼짐 | 전역 셰이더 값 `_SpringCenter`, `_SpringRadius` 를 키운다. 머티리얼은 반지름 안을 봄으로 바꾸고, 꽃 같은 소품은 반지름이 닿으면 자라난다 |

전역 셰이더 값 이름과 방식은 아트와 맞춰야 한다. 머티리얼(셰이더 그래프)이 이 값을 읽어야 하기 때문이다.

### 4.16 사운드

- 신호마다 소리가 붙는다 (§3.1). 소리는 각 장치의 `AudioSource` 를 신호 이벤트로 재생한다. 별도의 사운드 매니저는 처음에는 만들지 않는다.
- 배경음과 환경음은 스테이지 설정에 둔다. 기획서에는 배경음에 관한 내용이 없다.

### 4.17 시간 값과 플레이타임 (§1.4, §3.2)

`GameTuning` 에 모든 시간과 속도를 모은다. 초안 값은 기획서 그대로다.

| 값 | 초안 | 횟수 | 합 |
|---|---|---|---|
| 아기 깨어남 | 10초 | 4 (인트로 + 스테이지 시작 3회) | 40초 |
| 기울어진 고목 | 30초 | 1 | 30초 |
| 잠든 토끼 가족 | 30초 | 1 | 30초 |
| 안개 | 구간당 30초 | 2 (3-1, 3-2) | 60초 |
| 구름 | 40초 | 1 | 40초 |
| 합 | | | 200초 = 3분 20초 |

기획서의 "약 3분 20초" 와 같다. 목표는 약 3분이다 (§3.2). 이 밖에 아기 걷는 속도, 새 속도, 울음 거리, 우산 반지름, 안개 걷히는 폭, 신호 시점 비율도 여기에 둔다. 한 판이 최대 10분이라, 값을 바꿀 때 코드 수정 없이 바로 시험할 수 있어야 한다.

### 4.18 개발용 도구

- 시간 배속 (누를 때마다 1배 → 2배 → 3배 → 1배), 다음 스테이지로 건너뛰기, 지금 장치를 저절로 풀기, 지금 장치를 새가 푼 것으로 풀기.
- 네 가지는 화면 위쪽 가운데의 버튼 줄이다. 버튼에 마우스를 올리면 설명이 나온다. 버튼 줄을 누른 클릭은 새를 움직이지 않는다. 키보드 F1 ~ F4 도 같은 일을 한다.
- 길, 궤적, `StopPoint`, 길 범위, 카메라 구간과 트리거를 Gizmo 로 그린다.
- 개발 빌드와 에디터에서만 켠다. 게임 조작은 여전히 마우스 두 버튼뿐이다 (§15.6).
- `TreeGenerator`: 씬 오브젝트에 붙이는 나무 배치 도구. 프리팹 목록, 구역(씬 뷰에 테두리), 간격, 흔들림, 크기 범위, 무작위 회전, 시드를 인스펙터에서 정한다. Generate 는 그 도구가 만든 나무를 지우고 새로 놓는다. Clear 는 그 도구가 만든 나무만 지운다. 둘 다 Ctrl+Z 로 되돌린다. `Sam_Test` 빌더도 이것을 쓴다.

### 4.19 웹 빌드에서 확인할 것

- 우클릭할 때 브라우저 메뉴가 뜨지 않는지 본다. 뜨면 웹 템플릿에서 막는다.
- 브라우저는 사용자의 첫 입력 전에는 소리를 막는다. 인트로의 눈 소리가 첫 클릭 전에 들리는지 본다.
- 안개 텍스처 갱신과 눈 파티클의 비용을 실제 브라우저에서 잰다.

## 5. 정한 것과 남은 질문

기획서 16장의 미정 사항 중 대부분은 수치나 연출이라, 코드는 그 값을 바꿀 자리만 두면 된다. 아래는 코드 구조에 영향을 주는데 기획서에 답이 없던 것이다. 2026-10-27 에 사용자가 Q11 을 뺀 나머지를 정했다. 근거와 버린 대안은 [ADR 0003](decisions/0003-구현-계획-질문의-답.md) 과 [ADR 0004](decisions/0004-안개-자연-해결-규칙.md) 에 있다.

| 6. 마무리 | `Main.unity` 에 스테이지 프리팹 모으기, 아트와 소리 붙이기, 웹 빌드, 시간 값 맞추기 | 웹에서 적극적으로 약 5분, 기다리기만 약 8분 (§1.4) |

1단계와 2단계는 서로 의존하지 않으므로 사람이 둘이면 나눠서 할 수 있다. 3·4·5단계도 1단계의 틀만 있으면 서로 따로 할 수 있다.

계획 밖에서 바뀐 것:

- 카메라가 새를 따라가고, 장치가 풀리기 전에는 장치 너머로 가지 못한다 (ADR 0005, 작업 기록 07)
- 기믹 구간에서 카메라가 좁은 범위로 잠긴다. 아기 기준 한계를 없앴다. 새는 길 안에 있고, 장치가 풀리기 전에는 벽을 넘지 못한다 (ADR 0007, 2026-10-27 작업 기록 10)
- 카메라 구간은 아기가 아니라 새가 트리거를 넘으면 잠긴다. 새를 막는 벽은 없앴다. 고목 구간의 범위를 크게 줄였다 (ADR 0008, 2026-10-27 작업 기록 13)
- 안개 맵(`Sam_Fog_Test`)은 기본 사항이 정해질 때까지 다시 만들지도, 시험하지도 않는다. 사용자가 안개 맵 작업을 시작한다고 할 때 지금 코드로 다시 만든다
- 빛나는 공간은 따로 구간을 두지 않고 마지막 장치 바로 뒤에 둔다 (ADR 0006, 작업 기록 08)
- 개발용 배속은 버튼으로 1·2·3배를 돈다. 개발용 기능은 화면 위쪽 버튼 줄이다 (2026-10-28 작업 기록 05)
- 길가 나무는 4종이고 종류마다 잎 없는 것과 있는 것이 있다. 지금은 색으로 나눈다. 위로 갈라지는 가지가 있는 줄기다. 길 양쪽 가장자리에 두 줄로 촘촘히, 그 바깥 땅에는 듬성듬성 무작위로 두고, 이웃끼리는 종류가 다르다 (ADR 0013). 카메라 쪽 나무가 길을 가려도 된다. 스테이지 1 은 잎 없는 4종을 쓴다 (2026-10-28 작업 기록 01 ~ 03). 2026-10-29 에 토미의 3종으로 바꿨다. 모든 스테이지가 잎 없는 것을 쓴다 (ADR 0019)
- 나무 배치는 `TreeGenerator` 컴포넌트가 한다. 다른 씬에서도 붙여서 쓴다 (2026-10-28 작업 기록 06)
- 가려진 새는 실루엣으로 보인다 (2026-10-28 작업 기록 03)
- 새는 길가 나무의 가지에 앉고, 가만히 2초면 가까운 가지로 간다. Q7 을 뒤집었다 (ADR 0009, 2026-10-28 작업 기록 04)
- 새를 아트의 모델과 애니메이션으로 바꿨다 (2026-10-27 작업 기록 11)
- 아기를 아트의 소녀 모델과 애니메이션으로 바꿨다. 클립을 쓰는 자리는 4.3 에 있다 (2026-10-28 작업 기록 07)
- 스테이지를 한 줄의 길로 잇고 순간이동을 없앴다. 새는 다음 장치까지만 간다. `Sam_Test` 에서 먼저 했고, 디렉터의 메인 맵이 오면 옮긴다 (ADR 0010, 2026-10-28 작업 기록 08)
- 막힌 곳 너머를 누르면 새가 가까운 가지에 앉아 고개를 젓는다. 제자리 비행을 `Bird_Hover` 로 바꿔 시험 중이다 (ADR 0011, 2026-10-28 작업 기록 09)
- 계절 단계 시스템(`Season`)과 디버그용 빨간 칠(`SeasonDebugTint`). 실제 환경 변화는 아직 없다 (4.15절, 2026-10-28 작업 기록 10)
- 새는 장치가 아니라 스테이지 단위로 막는다. 지금 스테이지의 빛나는 공간까지만 간다 (ADR 0012, 2026-10-28 작업 기록 11)
- 새가 다니는 범위를 길 옆 땅(x ±13)까지 넓히고, 땅(x ±22)과 바깥 나무를 늘렸다 (ADR 0013, 2026-10-28 작업 기록 12). 2026-10-29 에 x ±25 로 넓혔다 (ADR 0019)
- 카메라 구간은 트리거 띠에 들어오면 잠기고 더 넓은 캠락 구간을 나가면 풀린다. 물을 눌러도 새가 간다 (ADR 0014, 2026-10-28 작업 기록 13)
- 새는 고정 상자가 아니라 실제 화면 안에 둔다. 고목의 카메라 구간은 맵 가장자리 가까이에서 풀린다 (ADR 0015, 2026-10-28 작업 기록 14)
- 거절은 누른 자리가 아니라 새가 막힌 선에 닿았을 때 한다 (ADR 0016, 2026-10-28 작업 기록 15)
- 비교용 브랜치 `sam-fixed-camera` 에 구간별 고정 카메라 버전을 두었다. 카메라만 다르다 (작업 기록 10). `sam` 과 함께 원격에 올렸다
- 인트로를 장치 없는 스테이지로 만들고, 계절을 5단계로 했다. 눈은 인트로에서만 내린다 (ADR 0018, 2026-10-29 작업 기록 01)
- 땅을 커다란 터레인 하나로, 나무를 토미의 3종으로 바꿨다. 카메라가 보는 곳 끝까지 숲이다. 새의 범위는 길 폭의 5배(x ±25)다 (ADR 0019, 2026-10-29 작업 기록 01)

남은 일과 열린 문제:

- Q11 (엔딩의 마지막 울음) 은 기획 담당에게 물어야 한다
- 카메라가 기획서 §2.5 와 다르다. ADR 0007, 0008 은 디렉터의 요청이지만 아직 시험 중이다. 디렉터의 피드백을 기다린다
- 임시 값: 새의 화면 가장자리 여유(`BirdController` 의 `screenMargin`), 카메라 구간의 트리거와 범위, 전환 시간 1초, 안개의 걷히는 폭·다시 잇는 범위·동물 대답 범위
- 빌더가 돌 때마다 시험용 반투명 머티리얼(`ClickMarker.mat`, `RestLight.mat`, `AnimalGlow.mat`)의 `_SrcBlend` 값이 바뀐다. 빌더가 블렌드 값을 직접 넣는 것과 에디터의 자동 조정이 다른 값을 쓰는 것으로 보인다. 커밋하지 않고 두었다. 빌더를 손볼 때 고친다
- 실제 마우스로 손으로 해 본 것은 사용자의 시험뿐이다. 나머지 확인은 가상 마우스로 했다
- 아기 걷기에서 발이 미끄러진다. 걷기 클립의 보폭은 발이 미끄러지지 않는 속도가 약 0.1 m/s(이 게임의 크기로 0.08 m/s)인데, 아기는 1.2 m/s 로 걷는다. 아트에게 보폭이 큰 걷기를 받거나 걷는 속도를 다시 정해야 한다
- 깨어날 때마다 `Girl_GetUp` 12.6 초를 기다린다. 4번이면 약 50초가 플레이타임에 더해진다(§1.4)
- 나무 1645 그루(렌더러 약 8900)와 인트로의 눈 파티클 약 2.6 만 개의 웹 성능을 봐야 한다. 에디터에서는 약 105 FPS 였다
- 토미의 나무(5.5 m)에 비해 새(날개 폭 2.2 m)가 크다. 크기는 아트와 맞춰야 한다
- 나무 머티리얼(`ArnoldStandardSurface`)에 `_BaseColor` 가 없어 디버그용 빨간 칠이 나무에 먹지 않는다
- 토미의 잎 있는 나무 FBX 를 가져올 때 `LeafCard_00N` 이름이 겹친다는 경고가 난다. 동작에는 문제가 없다
- 4번 나무 프리팹을 지워서, 서현 님의 시험 씬 둘(`Seohyeon_Watercolor_Test`, `Seohyeon_Pastel_Test`)에서 그 나무들이 빠진 프리팹으로 나온다. 1 ~ 3번은 토미의 나무로 바뀌어 보인다
- `Sam_Fog_Test` 의 아기는 예전 회색 캡슐 그대로라 지금 코드로는 Animator 가 없어 동작하지 않는다. 안개 맵을 다시 만들 때 같이 바뀐다

## 7. 위험

| 위험 | 대응 |
|---|---|
| 안개 구간이 가장 복잡하다. 궤적, 판정, 표시가 얽혀 있다 | 2단계로 먼저 따로 시험한다. 격자 하나를 판정과 표시의 공통 원본으로 둔다 |
| 기다리기만 하면 지루할 수 있다 (§3.1) | 신호 시점과 시간을 `GameTuning` 에서 바로 바꿔 가며 시험한다. 개발용 배속으로 전체를 자주 돌린다 |
| 새가 화면 밖으로 나가거나 나무에 가린다 | 새는 화면 밖으로 못 나간다 (Q3, ADR 0005, ADR 0007). 가림은 카메라 각도와 소품 배치를 정할 때 같이 본다 |
| 웹 성능 (파티클, 투명한 안개 여러 장, 텍스처 갱신) | 4.19 를 1단계가 끝나면 바로 한 번 확인한다 |
