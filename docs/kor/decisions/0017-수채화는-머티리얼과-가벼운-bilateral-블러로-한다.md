# 0017. 수채화 표현은 머티리얼 셰이더와 가벼운 bilateral 블러로 한다

- 상태: 채택
- 날짜: 2026-10-27
- 관련: `Assets/01_Arts/Shaders/WatercolorLit.shader`, `Assets/01_Arts/Shaders/WatercolorBlur.shader`, `Assets/02_Scripts/Rendering/`

## 맥락

화면 전체를 수채화처럼 보이게 하려고 Blender 의 Anisotropic Kuwahara 를 따라 한 화면 공간 후처리를 먼저 만들었다(구조 텐서,
타원 커널, 안료·번짐·종이·붓결 합성). 목표 플랫폼이 웹 브라우저라 GPU 시간이 빠듯하다. 사용자는 이 필터가 실시간 게임에
무겁다고 보고, 머티리얼에서 수채화 느낌을 내고 후처리는 비슷한 색끼리만 섞는 가벼운 블러로 바꾸자고 했다.

1080p, RTX 3050 Ti Laptop, Play 모드 GPU Recorder 로 잰 패스별 GPU 시간:

| 방식 | GPU 시간 |
|------|----------|
| Kuwahara, 전체 해상도 | 약 14 ms (Kuwahara 패스만 11.8 ms) |
| Kuwahara High / Medium / Low (절반 해상도) | 1.25 / 0.95 / 0.60 ms |
| Bilateral 블러 3x3 | 0.135 ms |
| Bilateral 블러 3x3 + 깊이 | 0.26 ms |

`WatercolorLit` 머티리얼은 같은 장면에서 URP Lit 보다 프레임 시간이 약 1.3 ms 짧았다(편집 모드 벽시계 측정이라 오차가 크다).
스페큘러와 환경 반사를 계산하지 않기 때문이다.

## 결정

사용자가 정했다.

**물체마다 `ThatGameJam/WatercolorLit` 머티리얼로 수채화 명암과 안료 얼룩을 내고, 후처리는 `WatercolorBlur` 한 패스(3x3
bilateral)만 쓴다.** 렌더러(PC, Mobile)에는 `WatercolorBlurFeature` 를 켜 두고 `WatercolorKuwaharaFeature` 는 꺼 둔 채
남긴다. 두 피처 모두 Volume 에서 켜야 동작하므로 `Main.unity` 는 바뀌지 않는다.

## 대안

**대안 1. Anisotropic Kuwahara 를 계속 쓴다.**
보류했다. 절반 해상도로 낮추고 노이즈를 텍스처로 바꾼 뒤에는 0.6~1.25 ms 까지 내려왔고, 붓 터치처럼 색 덩어리가 지는 모양은
블러로는 나지 않는다. 그래도 블러보다 4~9 배 비싸고, 웹 브라우저에서는 더 느릴 수 있다. 코드는 남겨 두어 렌더러에서 켜면
바로 비교할 수 있다.

**대안 2. 블러를 절반 해상도로 돌린다.**
버렸다. 블러는 샘플 9 개짜리 한 패스라 0.135 ms 다. 절반 해상도로 가려면 축소와 확대 패스가 더 필요해서 아낄 몫보다 더 든다.

**대안 3. 머티리얼만 쓰고 후처리를 하지 않는다.**
쓸 수 있다. 블러는 Volume 에서 끄면 된다. 블러는 물체 사이 색 경계를 조금 풀어 주는 정도라, 장면을 보고 정하면 된다.

## 결과

**얻는 것.**

- 후처리 비용이 0.135 ms(깊이 포함 0.26 ms)다
- 머티리얼 단위로 그림자 색, 안료 세기, 붓결을 아티스트가 조절할 수 있다
- 안료 얼룩이 월드(또는 오브젝트) 공간에 붙어 있어 카메라가 움직여도 화면에서 미끄러지지 않는다

**치르는 것.**

- 수채화로 보이려면 모든 모델이 `WatercolorLit` 를 써야 한다. 블렌더에서 가져온 머티리얼을 하나씩 바꿔야 한다
- 잎 빌보드(`LeafBillboard.shader`)는 따로 만든 셰이더라 안료 얼룩이 없다
- 스페큘러와 환경 반사가 없어 URP Lit 보다 비스듬한 면이 어둡고 진하게 보인다. Base Color 로 맞춘다
- 머티리얼은 메인 라이트 외 방향광을 무시한다(Forward+ 의 추가 방향광 루프를 넣지 않았다)
- WebGL 빌드에서는 아직 확인하지 않았다
